# Spark — архитектура ядра

## Принципы

1. **Ядро не знает про UI.** `src/` не импортирует DOM, React, Canvas. Его можно запустить в Node, браузере, Web Worker, на сервере (проверка решений учеников).
2. **Состояние мира — неизменяемые данные.** `SystemState` — обычный JSON: снапшоты, undo/redo, реплей, сохранение «лабораторки» в файл, отправка в Worker — бесплатно.
3. **Физика — чистые функции.** `solver.step(state, dt) → newState`. Нет скрытого состояния ⇒ детерминизм и тесты против аналитических решений.
4. **Единицы — в типах.** Внутри всё в СИ (`Kelvin`, `Joules`, …, branded number). °C, граммы, кДж — только на границе (фабрики, UI).
5. **Домены — плагины.** Термодинамика, электричество, механика, позже химия — отдельные папки `src/domains/*` со своими сущностями, связями, формулами и солвером. Ядро о них не знает.
6. **Сцена = граф.** Узлы — `Entity`/`Device` с портами, рёбра — `Connection` (провод, тепловой контакт, верёвка). Порт и связь имеют `domain`, `validateState` не даст соединить тепловой порт с электрическим.

## Ключевые типы

| Тип | Что это | Пример |
|---|---|---|
| `Entity<K, P, S>` | объект мира: `kind` + `params` (настраивает ученик, физика не меняет) + `state` (эволюционирует) + `transform` | кубик меди |
| `Body` | `Entity` с `params.mass` | груз, тележка |
| `Device` | `Entity` с портами `PortSpec { name, domain }` | резистор (2 электр. порта), нагреватель |
| `Connection` | ребро между `PortRef`-ами, со своим `kind`/`params` | провод, тепловой контакт G=30 Вт/К |
| `SystemState` | `{ time, step, environment, entities, connections }` | весь мир в момент t |
| `Solver` | `step(state, dt) → state`, не трогает часы | `createThermalSolver()` |
| `Simulation` | цепочка солверов + владелец времени | `createSimulation({ solvers, fixedDt })` |

Разделение `params` / `state` даёт «Сброс эксперимента» = оставить params, вернуть исходный state.

## Модуль 1: теплообмен

Каждый тепловой объект — узел с теплоёмкостью `C = m·c` (у резервуара ∞), температурой `T` и мощностью источника `P`:

```
C_i · dT_i/dt = P_i + Σ_j G_ij · (T_j − T_i)
```

Интегрирование — явный Эйлер с **автоматическим подшагом** (h < C/ΣG — условие устойчивости). Каждая связь переносит ровно +q/−q, поэтому энергия сохраняется до машинной точности; это проверяется тестом `ΔU = E_нагревателя − Q_в_комнату`.

Почему теплообмен первым, а не цепь: это настоящая эволюция во времени (`tick` осмысленен), математика — одна строка, а результат сразу проверяется школьными формулами. Электрическая цепь постоянного тока — алгебраическая задача (метод узловых потенциалов, СЛАУ), она идёт вторым модулем и подключается к термодинамике через джоулево тепло.

### Компоненты: одно вещество — одна модель

Каждое вещество — отдельный модуль в [src/components/](../src/components/) по общему контракту [`Component`](../src/components/types.ts):

- **паспорт** — название, формула и состав по элементам (молярная масса **вычисляется** из стандартных атомных масс, а не вписывается), Wikidata;
- **агрегатные состояния** — плотность, теплоёмкость, теплопроводность для твёрдого, жидкого, газа;
- **переходы** — плавление, кипение, сублимация, разложение, давление пара;
- **в воде** — растворимость, на какие ионы распадается и, если движок умеет считать раствор, собственная **модель раствора** (функции растворимости и замерзания живут в файле вещества);
- **электричество и магнетизм**, **опасности**, описание по уровням, допущения модели.

Каждое число — `SourcedValue` с источниками; тест [components.test.ts](../tests/components.test.ts) обходит все значения всех компонентов и сверяет их с цитатами, а также проверяет физическую правдоподобность (плавление ниже кипения, состояние при 20 °C, порядок плотностей).

Движок не спрашивает «это вода?» — он спрашивает модель («кипишь? при какой температуре? смешиваешься с водой?»). Новое вещество = новый файл + строка в реестре [index.ts](../src/components/index.ts). Остальные каталоги — **виды** на компоненты: тепловые материалы ([materials.ts](../src/domains/thermal/materials.ts)), полка лаборатории ([substances/catalog.ts](../src/substances/catalog.ts)); своих чисел у них нет. Полка может называть продукт по-своему: компонент — «вода», на полке — «дистильована вода».

Рецепты ([src/recipes/](../src/recipes/)) — «что взять и в какой пропорции» (морская вода = вода + 3,5 % соли). Это подсказки и ярлыки на полке, а не новые модели.

### Операции: одно действие — один модуль

«Нагріти до…», «Закип’ятити», «Випарити досуха», «Охолодити до…», «Заморозити», «Розплавити» — модули в [src/scenarios/operations/](../src/scenarios/operations/) по контракту [`Operation`](../src/scenarios/operations/types.ts). Операция сама знает:

- чем работает (нагреватель / охладитель / любой) и в какую сторону идёт температура;
- нужна ли целевая температура, какая стартовая разумна для вещества, с какой скоростью запускать;
- когда цель достигнута (`reached`) и чем опыт может закончиться вместо цели (масло дымит, а не кипит);
- почему цель невозможна заранее (`impossible`) — с текстом на всех языках;
- как считать «на бумаге» (`paper`: до какой температуры + сколько энергии сверху);
- глаголы итога в нужном роде, дополнительные строки («на дне осталось 36 г соли»), линии на графике.

Лаборатория ([thermal-lab.ts](../src/scenarios/thermal-lab.ts)), разбор и страница только спрашивают операцию. Тест-сторож [operations.test.ts](../tests/scenarios/operations.test.ts) не даёт коду вне папки операций ветвиться по их именам. Новая операция = новый файл + строка в реестре.

### Полка: всё из каталога, по семействам

Раздел «Речовина» на полке показывает весь каталог по семействам (`SUBSTANCE_FAMILIES`): рідини, розчини, солі й мінерали, метали й сплави, інші тверді тіла. Жидкость наливают в посуду образцом (до старта и только то, с чем выбранное действие возможно); твёрдое тело (брусок, соль) по нажатию готовится в панели «Додати під час досліду» с подходящей массой и температурой — его кладут в жидкость или подвешивают на динамометр, в том числе посреди опыта. Карточки тел — брусок своего цвета с символом, плотность из модели. Чтобы при росте каталога не было километровых списков, открыто одно семейство (образца или последнее открытое), остальные свёрнуты в заголовок с числом веществ; внутри — карусель по две карточки (та же карусель и столько же плиток, что у действий). При поиске открыты все семейства с совпадениями. Так же устроено оборудование: нагреватели, охладители, источники тока, посуда и «Вимірювальні прилади» (весы — на чём взвешивать; динамометр открывает панель, где подвешивают тело) сгруппированы по категориям каталога (побутові / лабораторні), открыта группа выбранного прибора.

### Теплообмен: смешивание и тепловой баланс

Металлы и сплавы (алюминий, медь, железо, сталь, латунь — плотность и теплоёмкость из источников) стоят на полке как **тела, которые кладут в жидкость** (`solid.metal`): образцом в посуде они не бывают. Брусок — отдельное тело-кубик, омываемое водой со всех сторон; по умолчанию его берут «з окропу», 100 °C. Горячая вода, налитая в холодную, смешивается сразу по уравнению теплового баланса.

Операция «Дочекатися рівноваги» ([settle.ts](../src/scenarios/operations/settle.ts)) — без прибора: ждёт, пока всё, что положили в жидкость, придёт к её температуре (±0,3 K — точность школьного термометра), а стенки посуды догонят воду (меньше десятой части разницы «вода − комната»: стекло устанавливается на ≈ 5 %, сталь на ≈ 2,5 %). Если ничего не положили — Профессор подсказывает, что сделать. Доска пишет формулу смеси (сразу, с числами), `Q = c·m·Δt` для каждого тела и в конце — сам баланс `c₁m₁(t₁ − θ) = c₂m₂(θ − t₂)`: отданное и полученное, разница ушла в посуду и воздух. Скачок температуры при доливании — смешивание, а не нагрев: в `Δt` он не входит.

**Калориметр** — алюминиевый стаканчик во внешнем стакане с воздушным промежутком (`VesselSpec.jacket`): теплота уходит наружу через слой неподвижного воздуха (его теплопроводность — из источников), затем в комнату; размеры и массы — оценки, школьные калориметры разные. На плиту и над огнём его не ставят — греют только изнутри кипятильником. В нём смешивание 50 → 48,5 °C (остаток забирает сам стаканчик), а за 10 минут с крышкой вода остывает втрое меньше, чем в стакане.

Готовые опыты могут класть что-то в посуду до старта (`Preset.setup`): «Змішуємо гарячу й холодну воду» (ровно 50 °C сразу после смешивания — и 47 °C в равновесии со стаканом) и «Алюміній чи мідь» (ответ сравнивает с прогоном «в уме» медного бруска той же массы). Сессия теперь сохраняет снимок состояния сразу после команды, меняющей вещество, — начальная температура бруска точная.

### Плотность и плавание (механика, 7 класс)

Маленький домен [src/domains/mechanics/](../src/domains/mechanics/): формулы `ρ = m/V`, `P = m·g`, `F_A = ρ·g·V` и доля погружения `ρ_т/ρ_р`, закон Архимеда с историей (Wikidata, «Про плаваючі тіла», бл. 246 р. до н. е.), `g` — стандартное (CODATA). Формулы привязаны к цитатам обеих программ (7 класс). Тела в жидкости ([measuring.ts](../src/scenarios/measuring.ts)) плавают или тонут по плотности: лёд — на ≈ 92 % под водой, сосна — наполовину, металлы на дне. Уровень по делениям считает жидкость, лёд и тела так, как их видит мензурка: плавающее тело вытесняет свою массу жидкости, утонувшее — свой объём; поэтому растаявший лёд уровень не меняет — это проверяет тест.

Измерения — команды-измерения, как взвешивание: `lab.read-level` (мерный цилиндр 100 мл с делением 1 мл; у стакана грубые деления по 25 мл) и `lab.hang` (динамометр 5 Н с делением 0,1 Н: тело в воздухе — `P = m·g`, в жидкости — меньше на архимедову силу; плавающее тело оставляет пружину свободной). Показания несут числа, из которых получены (`MeasurementRecord.inputs`), поэтому доска пишет `V = V₂ − V₁`, `m = m₂ − m₁`, `ρ = m/V` и архимедову силу двумя способами — по показаниям (`P − P′`) и по закону (`ρ·g·V`). На сцене — плавающие тела у поверхности, метка уровня, динамометр с телом над посудой или в жидкости. Новые тела на полке: сосновый брусок и стеклянный шарик (плотности из источников). Мензурку не нагревают.

**Пошаговые процедуры** (`Preset.guided`): измерительный опыт ведёт Профессор — без «Старта», каждый шаг плана — кнопка под сценой («Крок 2 з 5: подивись на поділки…»), опускание тела — отдельный шаг (брусок падает в мензурку, вода плавно поднимается). Каждое показание сначала записывается на доску, как в тетради (`m₁ = …`, `V₁ = …`), затем выводы (`m = m₂ − m₁`, `V = V₂ − V₁`, `ρ = m/V`); когда всё измерено, приборы отодвигаются — доску видно целиком. Прогноз, если он есть, предлагается над первым шагом; ответ и вердикт — в той же панели в конце. «Що це за метал?» заканчивается **таблицей густин** (`choicesAt: 'end'`, `choiceTable: 'density'`): все твёрдые тела полки по плотности, ученик сам находит своё «Це він!», верный ответ — ближайшая к измеренной плотность. Шаг плана может быть и операцией («⏳ Чекати, поки лід розтане»: своё название и скорость, медленнее — чтобы успеть увидеть); пока она идёт, панель говорит «стеж за посудом». Опыт со льдом идёт так: уровень воды → кубик падает и всплывает → уровень → ждём, пока растает → уровень; на доске `ΔV = V₃ − V₂ = 0`. Всё, что происходит, показано постепенно: тающий кубик уменьшается и бледнеет, соль опускается крупинками и растворяется облачком, вода поднимается плавно. Звуки ([web/sounds/](../web/sounds/index.ts)) синтезируются в браузере (Web Audio, без файлов): «бульк», когда тело касается воды (ниже — у тела побольше), тихое шипение, пока растворяется соль; кнопка 🔊/🔇 в шапке, выбор запоминается. Профессор «бормочет» каждую новую реплику (слоги по числу слов, не дольше ≈ 1,5 с; в конце вопроса голос поднимается), и у него двигается рот; голос выбирают в шапке: озвучення (встроенный голос браузера читает реплику на языке страницы; если такого голоса нет — бурмотіння), бурмотіння (мягкий «голосовой» источник с убывающими гармониками, с хрипотцой — дыхание через гласные и неровное дребезжание, согласная в начале слога, гласная с тремя формантами, лёгкое дрожание, интонация опускается к концу фразы, ударные слоги длиннее), басовитий дідусь, мультяшне щебетання, робот, посвистування или мовчки; консоль `voice`. Ничего не звучит до первого клика или клавиши — браузер иначе сыграл бы всё накопленное разом. Когда опыт закончен (ничего не осталось в плане), под сценой появляется «🔄 Новий дослід»: губка проходит по доске и стирает записи, затем всё ставится заново с начала (готовый опыт — со всеми шагами). Неизвестный металл — медь: ближайший сосед в таблице (латунь) отличается на 4,5 %, больше погрешности мензурки на 20 мл; железо и сталь (7874 / 7850) так не различить.

Готовые опыты 7 класса: «Чи зміниться рівень води, коли лід розтане?», «Що це за метал?» (брусок без подписи: ученик взвешивает и смотрит на деления, ответ — по его же показаниям), «Де архімедова сила більша?» (пресная и солёная вода). Шаги-измерения плана останавливаются на показании; если план закончился измерением, вопрос получает ответ сразу. Ответы готовых опытов получают все показания опыта (`PresetRun.readings`).

### Протокол: опыт как цепочка шагов

Один образец, несколько шагов: «закипятить → досыпать соль → выпарить досуха», «закипятить на плите → охладить в холодильнике → заморозить в морозилке» ([protocol.ts](../src/scenarios/protocol.ts)). Шаг — операция со своим прибором или добавление вещества. Между операциями посуда «переезжает»: `configureStep` берёт свежую установку для нового шага и переносит в неё всё вещество как есть (температура, состав, лёд, добавленное) и комнату; приборы — новые, но та же плита остаётся горячей. Каждый шаг — отдельный прогон со своим итогом, балансом энергии и разбором; время в итогах считается от начала шага.

Если цель так не достичь, лаборатория не просто сообщает об этом, а **предлагает остановиться или изменить условия** ([lab-fixes.ts](../src/scenarios/lab-fixes.ts)). Операция говорит, чего ей не хватает (`needs`: окружение холоднее X, другая цель, нагрев), а лаборатория подбирает из каталога конкретные варианты — «морозилка −22 °C» для морской воды при −18 °C — и оставляет только те, при которых цель достижима. Если нагрев «застрял» (потери сравнялись с мощностью), варианты — ручка на максимум, крышка, мощнее модель, меньше вещества, другой нагреватель — проверяются прогоном «в уме». Выбранный вариант продолжает опыт следующим шагом с тем же образцом. «Нет продвижения» — одна общая проверка (`noProgress`): медленное испарение считается продвижением только для «випарити досуха».

На странице протокол растёт по ходу опыта: шаг закончился → выбираешь слева другую операцию или прибор → «Продовжити». Смена операции посреди шага закрывает его и начинает следующий; смена вещества или посуды — новый опыт. Справа — журнал шагов.

### Записи: сохранить цепочку и повторить

Опыт можно записать ([recording.ts](../src/scenarios/recording.ts)): для каждого шага — его настройки, все команды с точной секундой от начала шага (ручка, досыпанная соль; сделанное в паузе после шага относится к этой паузе) и как шаг закончился (`'goal'` — дошёл до цели, число — остановлен через столько секунд). Физика детерминирована, поэтому повтор (`replayStep` / `replayRecording`) даёт тот же результат до последнего знака: первый шаг — со свежей установки, каждый следующий — из состояния, где закончился предыдущий (`configureStep`). Запись — JSON (`format: 'spark-recording'`, `version: 1`); `parseRecording` проверяет чужой файл по каталогам, прежде чем запускать.

На странице: «💾 Зберегти дослід» в протоколе, список «Мої записи» (▶ повтор шаг за шагом с анимацией, ⬇ файл, 🗑, ⬆ загрузить файл), хранение в `localStorage` (`spark.recordings`). В консоли — `save <name>`, `records`, `replay <n>`. Любой собственный выбор пользователя прерывает повтор.

### Взвешивание: измерение как команда

Весы — прибор с паспортом ([scales.ts](../src/equipment/scales.ts)): кухонные (5 кг, деление 1 г) и лабораторные (620 г, 0,01 г), числа — из листингов производителей. Взвешивание ([weighing.ts](../src/scenarios/weighing.ts)) — команда `lab.weigh` вида `measurement`: состояние не меняет, а показание (масса посуды со всем содержимым, округлённая до деления; выше предела — «перегрузка») кладёт в трассу как `MeasurementRecord`. Поэтому взвешивания попадают в журнал шага, в протокол, в записи и повторяются вместе с ними. Масса считается по телам вещества: посуда, крышка, образец (лёд и соль внутри), добавленные куски — испарившаяся и выкипевшая вода уходит из образца, и весы это видят. В протоколе взвешивание — шаг `{ kind: 'weigh', scale }`; на странице — кнопка «⚖ Зважити», консоль `weigh [kitchen|lab]`; на сцене посуда «переезжает» на весы с табло. Шаг, в котором время ещё не шло, при смене действия собирается заново с теми же командами (соль, взвешивание) — пустых шагов в протоколе нет.

### Вопросы с вариантами и разбор всего опыта

У готового опыта есть варианты ответа на его вопрос (`Preset.choices`) — прогноз до старта. Какой вариант верный, не записано в пресете: ответ (`PresetAnswer.correct`) выводит его из прогона модели, а тест проверяет, что прогон всегда выбирает один из вариантов. Так как верный вариант известен только после прогона, вариантов у прогноза не больше четырёх. Вопросы, на которые страница может ответить сразу (после взвешивания «куди поділися ці грами?»), берут четыре случайных варианта из пула, правильный — всегда среди них; порядок зависит от ключа вопроса и не меняется между кадрами. На неверный вариант Профессор объясняет, почему это не так, и предлагает попробовать ещё.

Подробный разбор («Поясни») начинается с хода опыта ([lab-course.ts](../src/scenarios/lab-course.ts)): каждый шаг с действиями до, во время и после него (взвешивания, досыпанное, ручка) и итогом — температура, лёд, сколько воды ушло в воздух, масса содержимого. Затем — последний шаг подробно, а предыдущие шаги — свёрнутыми полными разборами.

### Доска над столом

На стене сцены висит доска ([lab-board.ts](../src/scenarios/lab-board.ts)) — от верха до столешницы и почти во всю ширину: стена рисунка прозрачна, доска висит под ним, а стол, приборы и Профессор стоят перед ней. Доска не выдвигается: кнопка на краю стола «👀 Подивитися на дошку» уменьшает всё, что стоит на столе, и отодвигает к правому краю, а Профессор отступает влево, становится боком (рисунок в профиль, руки за спиной) и читает; пока он читает, его реплика спрятана и сценки скуки не начинаются. «↩ Повернутися до досліду» возвращает всё на место. На доске — формулы того, что происходит в текущем шаге. Шаг делится на фазы по записанным состояниям — всё твёрдое, всё жидкое, и то и другое — и каждая фаза получает строку в порядке, в каком случилась: `Q = c·m·Δt` (нагрев/охлаждение льда или жидкости), `Q = λ·m` (плавление/кристаллизация), `Q = L·m` (кипение, от 0,1 г выкипевшего), `I = U/R` и `Q = I²·R·t` (ток), `m = m₁ + m₂` (последнее взвешивание). Пока фаза идёт, на доске только формула; числа этого прогона дописываются, когда фаза закончилась («формула отработала») — тоже мелом. Константы — из моделей веществ (лёд в солёной воде — это замёрзшая вода, его данные берутся у воды). Новый шаг — чистая доска.

Доска добавляет и энергию прибора: в конце шага с нагревателем — `E = P·t` (сколько отдал нагреватель; P — средняя мощность за шаг) и `η = Q/E` (какая доля досталась самому веществу — то же число, что в балансе энергии разбора). Пишет её шрифт Caveat (SIL OFL 1.1, файлы и лицензия в `web/fonts/caveat/`, сборка вкладывает их в страницу). Пока Профессор читает, он ведёт головой вдоль строк и кивает, когда дописываются числа.

Чтобы сцене хватило места, она выше (больше стены сверху; предметы того же размера — меняется только видимая область рисунка), а график сворачивается: пока идёт опыт, видны ручка и плитки показаний; когда шаг закончился, график разворачивается и мигает 👇 — «результаты внизу». Обе боковые панели сворачиваются кнопкой в собственной строке заголовка в узкую полоску вровень с другими колонками.

### «До речі!..» — газета Профессора

После двух сценок скуки Профессор восклицает «До речі!..», и открывается страница старой газеты ([newspaper.ts](../web/newspaper.ts)): кто из учёных или изобретателей родился в этот день (лента Википедии «цей день», отбор по описанию), или справка о веществе или учёном самой лаборатории — темы берутся по Wikidata-идентификаторам компонентов и людей из истории законов. Текст каждый раз загружается живьём из Википедии (на языке страницы) и нигде не сохраняется; внизу — статья и лицензия (CC BY-SA 4.0). Статьи о российских и советских фигурах не показываются. В пределах визита статьи не повторяются. Без интернета — история одного из законов лаборатории (тексты Spark, даты по Wikidata). Кнопка «📰 Газета» на краю стола открывает газету в любой момент («Свіжа газета!»); консоль: `news`.

### Смеси: считаем из компонентов, а не «модель на каждый раствор»

Раствор — не отдельное вещество, а тело с **составом** (`mixture: { water, salt, ice, crystals }`). Растворы на полке («морская вода», «10 %») — лишь рецепты `вода + соль` с долей соли; любую другую пропорцию получают, досыпая соль или доливая воду (`thermal.add` сливает их в одно тело, энергия сохраняется). Всё остальное следует из состава ([mixture.ts](../src/domains/thermal/mixture.ts), данные — модели [воды](../src/components/water.ts) и [хлориду натрію](../src/components/sodium-chloride.ts)):

1. **Свойства чистых компонентов** — вода (теплоёмкость, теплоты плавления и парообразования), NaCl (молярная масса, теплоёмкость).
2. **Общие законы для любой пары** — закон Рауля (соль понижает давление пара → кипение выше, испарение медленнее), сохранение массы и энергии.
3. **Данные о паре веществ — только там, где общих законов мало**: растворимость (сколько соли вообще растворится) и кривая замерзания до эвтектики −21,1 °C — из измерений, с источниками.

Энтальпия считается от жидкой воды и твёрдой соли при 0 °C (теплота растворения NaCl мала и не учитывается); температура и доли льда/кристаллов восстанавливаются из энергии бисекцией. Отсюда: рассол замерзает постепенно (полностью — лишь ниже −21,1 °C), кипящий раствор крепчает и греется выше 100 °C, а выпаривание досуха оставляет ровно растворённую соль. Следующий шаг — обобщить до «вода + любое растворённое вещество» (сахар, сода): для слабых растворов хватит молярной массы и числа частиц, на которые распадается молекула.

## Модуль 2: электричество (ток через жидкость)

Источник постоянного тока (батарейка 9 В, USB 5 В, лабораторный блок 0–30 В — [supplies.ts](../src/equipment/supplies.ts)) и два электрода в жидкости ([src/domains/electrical/](../src/domains/electrical/)):

- **проводимость** κ берётся из моделей компонентов: раствор соли — таблица CRC (20 °C) + поправка ≈ 2 %/К; дистиллированная вода — своё малое значение; лёд и изоляторы (масло, спирт) — ноль; проводит только жидкая часть;
- **сопротивление** R = K / κ, где K = L / A — постоянная ячейки (электроды 2 × 5 см на расстоянии 3 см → 30 1/м);
- **ток** I = (U − U_разл) / (R + R_внутр), не больше предела источника; ниже напряжения разложения (вода 1,23 В, рассол 2,19 В из стандартных потенциалов) тока нет;
- **теплота Джоуля–Ленца** I²R идёт в жидкость через «ведомый» тепловой источник: электрический решатель задаёт его мощность, тепловой — разносит (фазы, кипение, баланс энергии работают как обычно); домены не импортируют друг друга;
- **закон Фарадея**: из прошедшего заряда — объёмы газов (водород и хлор из рассола, водород и кислород из воды);
- **энергия источника** = тепло жидкости + химическая энергия газов + нагрев самого источника (проверяется тестом); батарейка разряжается (550 мА·ч).

Знания домена ([catalog.ts](../src/domains/electrical/catalog.ts), [laws.ts](../src/domains/electrical/laws.ts)): опір рідини R = K/κ, закон Ома с напряжением разложения, Джоуль–Ленц P = I²R, Фарадей n = q/(zF) — с цитатами программ МОН (8 клас) и историей открытий (Ом 1827, Джоуль 1840 и Ленц 1842, Фарадей 1833–1834) с источниками. Решатель пишет trace каждой формулы; тест пересчитывает их по каталогу. `LAB_KNOWLEDGE` объединяет тепловые и электрические знания для разбора.

Операция «Пропустити струм» задаётся длительностью; в протоколе её можно чередовать с нагревом и добавлением веществ («вода на горелке → соль → ток → нагрев → снова ток»).

## Страница: сцена, полка, готовые опыты

- **Сцена** ([web/scene.ts](../web/scene.ts)) — живой SVG-рисунок того, что стоит на столе: прибор (по полю `look` в каталоге оборудования), посуда с содержимым — уровень, цвет жидкости, лёд (плавает сверху), кристаллы соли, пузыри кипения, пар, газ на электродах, облачко хлора, термометр. Сцена только читает состояние; статичная часть перестраивается при смене установки, живые детали — каждый кадр, анимации на CSS. Рядом Профессор: настроение и реплика по событию (кипит, замерзает, ток, хлор, тупик, успех, следующий шаг плана).
- **Полка** — карусель операций (по две плитки, как все карточки), карточки с рисунками: бутылки веществ с формулой, миниатюры посуды той же графикой, что и сцена, значки приборов; плитки операций с иконками (иконку называет сама операция, поле `icon`), «капли» цвета жидкости у веществ, значки посуды и приборов.
- **Графика** лежит в [web/graphics/](../web/graphics/README.md) по тому, что изображено: `icons/` — простые значки отдельными `.svg`-файлами в папках `operations/`, `vessels/`, `devices/`, `instruments/` (имя файла — то, что пишут в `icon` / `look`; новый значок — новый файл); `professor/` — Профессор анфас и в профиль и страница-превью; `scene/` — рисунки стола: посуда, приборы, измерительные приборы, тела в жидкости, цвета, система координат; `shelf/` — картинки карточек полки. То, что зависит от опыта (цвет, уровень, показания), — код; неизменное — файлы. `web/scene.ts` только собирает рисунки и двигает живые детали.
- **Только совместимое** ([choices.ts](../src/scenarios/choices.ts)): операция сама решает, с какими веществами она возможна (`accepts`: плавить можно только то, у чего есть твёрдое состояние); прибор — какую посуду можно поставить (индукция — магнитный металл, плита — плоское дно, кипятильник и электроды — по ширине горла); в «Додати» — только то, что команда добавления действительно примет (пробный прогон). `fitChoices` приводит установку в согласованное состояние после выбора. Во время опыта вещество и посуда не меняются, а действия и приборы предлагаются только совместимые с ними.
- **Справка** ([web/reference.ts](../web/reference.ts)) выезжает поверх лаборатории по кнопке «i» на карточке: паспорт (формула, молярная масса из формулы, тип), свойства по агрегатным состояниям, переходы с теплотами, поведение в воде, электричество и магнетизм, безопасность, допущения модели; у рецепта — состав со ссылками на компоненты и свойства смеси, посчитанные моделью; у оборудования — характеристики. У каждого числа — степень проверки и номер источника со ссылкой; условия измерений и примечания к данным — для уровней «поглиблений» и «експерт».
- **Консоль** ([web/console.ts](../web/console.ts)) — выезжает снизу по кнопке `>_` в левом нижнем углу, высота меняется перетаскиванием верхнего края (или стрелками) и запоминается, Esc закрывает. Команды по-английски (украинские названия команд — тихие синонимы), описания — на языке интерфейса: всё, что делается мышью (`action freeze`, `substance sea 0.2 l`, `device freezer -22`, `add salt 7 g`, `start`, `status`, `info chloride`, `preset 5`…), плюс `prof <scene>` — сыграть сценку Профессора сразу. Названия веществ и приборов понимаются на обоих языках и сокращёнными (начало слова или общая основа от 5 букв), Tab дописывает, ↑/↓ — история. Команды вызывают те же функции страницы, поэтому консоль подчиняется тем же правилам совместимости.
- **Готовые опыты** ([presets.ts](../src/scenarios/presets.ts)) — по классам и темам (8 клас: теплові та електричні явища; «Для всіх»): вопрос, установка, при необходимости — план следующих шагов, который ведёт Профессор, и формулы, чьи цитаты программы МОН показываются в карточке (`quoteHas` выбирает нужную тему). Тест прогоняет каждый опыт с планом и проверяет, чем он кончается в модели.

## Объяснения: «что участвовало в расчёте»

1. Солвер получает `ctx.trace` и пишет `TraceRecord`: id формулы из каталога, объекты, **точные аргументы** и результат. Без `trace` — нулевая стоимость.
2. `runExperiment` собирает статистику использования формул за весь прогон; `traceTick` пересчитывает один шаг из снимка с полной трассой («объясни момент t») — возможно, потому что физика чистая и детерминированная.
3. Тест `trace-consistency` повторно вызывает функцию каталога на аргументах из трассы и сверяет результат: объяснение не может разойтись с расчётом.
4. Формула → закон (`LawSpec`): формулировка по уровням, авторы (даты из Wikidata), история с цитатами, границы применимости. `role: 'associated'` — когда единственного «открывателя» нет.
5. `buildReport` строит `Block[]` по уровню (novice / school / advanced / expert), языку (`uk`, `en`) и стране программы (`UA`); консоль рендерит текстом, веб отрендерит карточками и KaTeX.
6. Ни ядро, ни тексты не предполагают конкретную страну: язык — ключ в `LocalizedText`, классы — только в `CurriculumRef` с кодом страны. Правила тона — [CONTENT_STYLE.md](CONTENT_STYLE.md).

Разбор «цель против результата» ([LEARNING_MODEL.md](LEARNING_MODEL.md)): солвер пишет `TransferRecord` — точную энергию по каждой связи за шаг; `runExperiment` суммирует их в `result.transfers`. `analyzeTemperature` раскладывает итоговую температуру тела на «простой расчёт» + вклад каждого участника (сумма сходится до 1e-9). `Expectation` (прогноз/цель) — необязательна; `solveKnob` бисекцией переигрывает опыт и находит, какой параметр как изменить.

Команды делятся на `control` (управление), `matter` (долить — приносит свою энергию) и `intervention` («режим бога» — энергия извне записывается), поэтому баланс энергии всегда сходится.

## Многодоменность (как будут жить вместе)

```ts
createSimulation({
  solvers: [electricalSolver, jouleCoupling, thermalSolver, mechanicsSolver],
  fixedDt: seconds(0.01),
});
```

Операторное расщепление: каждый солвер по очереди делает свой шаг. Связка доменов — через общие сущности: электрический решатель задаёт мощность «ведомого» теплового источника (`driven` burner), тепловой её разносит; домены не импортируют друг друга.

## Известные ограничения MVP (осознанно)

- Lumped-модель: одна температура на объект (без распределённых полей).
- Растворы — пока только вода + NaCl; смешивание разных жидкостей (вода + спирт) не моделируется.
- Явная схема: для очень жёстких сцен — ограничение подшагов и понятная ошибка; позже — неявный Эйлер.
- `kind` — строки, сущности домена проверяются type guard-ами. При росте числа доменов — реестр `EntityKindRegistry` с описанием параметров (для автогенерации панели свойств в UI).

## План MVP

**Шаг 1 — ядро + теплообмен в консоли (готово).** `npm test`, `npm run demo`.

**Шаг 1.5 — команды, трассировка, объяснения по уровням (готово).** `npm run experiment -- --level novice|school|advanced|expert|all --lang uk|en --country UA`.

**Шаг 1.6 — лаборатория с необязательными прогнозом/целью и разбором (готово).** `npm run lab -- --hot 0.3 --pot glass --goal 40`.

**Шаг 1.7 — браузер (готово).** `npm run web`: 6 нагревателей из каталога с источниками (электроплита, индукция, газ, кипятильник, горелка, спиртовка), ручка мощности во время опыта, живой график, «куда ушла энергия», объяснение по уровням, uk/en. `createExperimentSession` — пошаговый режим для UI; `runExperiment` построен поверх него.

**Шаг 1.8 — фазовые переходы и охлаждение (готово).** Тела хранят энтальпию: плавление/замерзание и кипение со скрытой теплотой, выкипание с уходом массы и энергии пара. Терморегулятор. Охладители. Лаборатория `scenarios/thermal-lab.ts` с пресетами «нагріти до / закип’ятити / охолодити до / заморозити / розплавити»; невозможные цели объясняются до запуска.

**Шаг 1.9 — испарение, прогноз/цель, добавление веществ (готово).** Испарение с открытой поверхности (масса и скрытая теплота уходят в воздух), под крышкой пар конденсируется и возвращается. Прогноз или цель по времени с разбором и проверенными вариантами «что изменить». Команда `thermal.add`: долить то же вещество, бросить замороженный кусок, налить несмешивающийся слой. Интерфейс: полка слева.

**Шаг 2 — электрическая цепь постоянного тока** (`src/domains/electrical/`):
`Battery(EMF, r)`, `Resistor(R)`, `Lamp`, `Switch`, `Ammeter`, `Voltmeter`, `Wire`.
Солвер — метод узловых потенциалов (MNA) + Гаусс с выбором ведущего элемента.
Тесты: закон Ома, последовательное/параллельное соединение, правила Кирхгофа, КЗ → понятная ошибка.
Coupling-солвер «джоулево тепло»: `P = I²R` резистора → тепловой узел. Сценарий: «нагреватель из нихрома в стакане воды».

**Шаг 3 — первый браузерный экран** (`apps/web/`, Vite + React/Canvas, ядро → `packages/engine`):
симуляция в Web Worker, `advanceRealtime` на `requestAnimationFrame`, панель параметров, график T(t) рядом с теоретической кривой, кнопки старт/пауза/×10/сброс.

**Дальше:** фазовые переходы (плавление/кипение), сериализация сцен + JSON Schema, механика (Верле: грузы, пружины, наклонная плоскость), реестр сущностей для автогенерации UI, химия (стехиометрия и кинетика как отдельный домен).
