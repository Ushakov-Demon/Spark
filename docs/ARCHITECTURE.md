# Spark — архитектура ядра

## Принципы

1. **Ядро не знает про UI.** `src/` не импортирует DOM, React, Canvas. Его можно запустить в Node, браузере, Web Worker, на сервере (проверка решений учеников).
2. **Состояние мира — неизменяемые данные.** `SystemState` — обычный JSON: снапшоты, undo/redo, реплей, сохранение «лабораторки» в файл, отправка в Worker — бесплатно.
3. **Физика — чистые функции.** `solver.step(state, dt) → newState`. Нет скрытого состояния ⇒ детерминизм и тесты против аналитических решений.
4. **Единицы — в типах.** Внутри всё в СИ (`Kelvin`, `Joules`, …, branded number). °C, граммы, кДж — только на границе (фабрики, UI).
5. **Домены — плагины.** Термодинамика, электричество, механика, позже химия — отдельные папки `src/domains/*` со своими сущностями, связями, формулами и солвером. Ядро о них не знает.
6. **Сцена = граф.** Узлы — `Entity`/`Device` с портами, рёбра — `Connection` (провод, тепловой контакт, верёвка). Порт и связь имеют `domain`, `validateState` не даст соединить тепловой порт с электрическим.

## Ключевые типы

| Тип | Что это | Пример |
|---|---|---|
| `Entity<K, P, S>` | объект мира: `kind` + `params` (настраивает ученик, физика не меняет) + `state` (эволюционирует) + `transform` | кубик меди |
| `Body` | `Entity` с `params.mass` | груз, тележка |
| `Device` | `Entity` с портами `PortSpec { name, domain }` | резистор (2 электр. порта), нагреватель |
| `Connection` | ребро между `PortRef`-ами, со своим `kind`/`params` | провод, тепловой контакт G=30 Вт/К |
| `SystemState` | `{ time, step, environment, entities, connections }` | весь мир в момент t |
| `Solver` | `step(state, dt) → state`, не трогает часы | `createThermalSolver()` |
| `Simulation` | цепочка солверов + владелец времени | `createSimulation({ solvers, fixedDt })` |

Разделение `params` / `state` даёт «Сброс эксперимента» = оставить params, вернуть исходный state.

## Модуль 1: теплообмен

Каждый тепловой объект — узел с теплоёмкостью `C = m·c` (у резервуара ∞), температурой `T` и мощностью источника `P`:

```
C_i · dT_i/dt = P_i + Σ_j G_ij · (T_j − T_i)
```

Интегрирование — явный Эйлер с **автоматическим подшагом** (h < C/ΣG — условие устойчивости). Каждая связь переносит ровно +q/−q, поэтому энергия сохраняется до машинной точности; это проверяется тестом `ΔU = E_нагревателя − Q_в_комнату`.

Почему теплообмен первым, а не цепь: это настоящая эволюция во времени (`tick` осмысленен), математика — одна строка, а результат сразу проверяется школьными формулами. Электрическая цепь постоянного тока — алгебраическая задача (метод узловых потенциалов, СЛАУ), она идёт вторым модулем и подключается к термодинамике через джоулево тепло.

### Компоненты: одно вещество — одна модель

Каждое вещество — отдельный модуль в [src/components/](../src/components/) по общему контракту [`Component`](../src/components/types.ts):

- **паспорт** — название, формула и состав по элементам (молярная масса **вычисляется** из стандартных атомных масс, а не вписывается), Wikidata;
- **агрегатные состояния** — плотность, теплоёмкость, теплопроводность для твёрдого, жидкого, газа;
- **переходы** — плавление, кипение, сублимация, разложение, давление пара;
- **в воде** — растворимость, на какие ионы распадается и, если движок умеет считать раствор, собственная **модель раствора** (функции растворимости и замерзания живут в файле вещества);
- **электричество и магнетизм**, **опасности**, описание по уровням, допущения модели.

Каждое число — `SourcedValue` с источниками; тест [components.test.ts](../tests/components.test.ts) обходит все значения всех компонентов и сверяет их с цитатами, а также проверяет физическую правдоподобность (плавление ниже кипения, состояние при 20 °C, порядок плотностей).

Движок не спрашивает «это вода?» — он спрашивает модель («кипишь? при какой температуре? смешиваешься с водой?»). Новое вещество = новый файл + строка в реестре [index.ts](../src/components/index.ts). Остальные каталоги — **виды** на компоненты: тепловые материалы ([materials.ts](../src/domains/thermal/materials.ts)), полка лаборатории ([substances/catalog.ts](../src/substances/catalog.ts)); своих чисел у них нет. Полка может называть продукт по-своему: компонент — «вода», на полке — «дистильована вода».

Рецепты ([src/recipes/](../src/recipes/)) — «что взять и в какой пропорции» (морская вода = вода + 3,5 % соли). Это подсказки и ярлыки на полке, а не новые модели.

### Операции: одно действие — один модуль

«Нагріти до…», «Закип’ятити», «Випарити досуха», «Охолодити до…», «Заморозити», «Розплавити» — модули в [src/scenarios/operations/](../src/scenarios/operations/) по контракту [`Operation`](../src/scenarios/operations/types.ts). Операция сама знает:

- чем работает (нагреватель / охладитель / любой) и в какую сторону идёт температура;
- нужна ли целевая температура, какая стартовая разумна для вещества, с какой скоростью запускать;
- когда цель достигнута (`reached`) и чем опыт может закончиться вместо цели (масло дымит, а не кипит);
- почему цель невозможна заранее (`impossible`) — с текстом на всех языках;
- как считать «на бумаге» (`paper`: до какой температуры + сколько энергии сверху);
- глаголы итога в нужном роде, дополнительные строки («на дне осталось 36 г соли»), линии на графике.

Лаборатория ([thermal-lab.ts](../src/scenarios/thermal-lab.ts)), разбор и страница только спрашивают операцию. Тест-сторож [operations.test.ts](../tests/scenarios/operations.test.ts) не даёт коду вне папки операций ветвиться по их именам. Новая операция = новый файл + строка в реестре.

### Полка: всё из каталога, по семействам

Раздел «Речовина» на полке показывает весь каталог по семействам (`SUBSTANCE_FAMILIES`): рідини, розчини, солі й мінерали, метали й сплави, інші тверді тіла. Жидкость наливают в посуду образцом (до старта и только то, с чем выбранное действие возможно); твёрдое тело (брусок, соль) по нажатию готовится в панели «Додати під час досліду» с подходящей массой и температурой — его кладут в жидкость или подвешивают на динамометр, в том числе посреди опыта. Карточки тел — брусок своего цвета с символом, плотность из модели. Чтобы при росте каталога не было километровых списков, открыто одно семейство (образца или последнее открытое), остальные свёрнуты в заголовок с числом веществ; внутри — карусель по две карточки (та же карусель и столько же плиток, что у действий). При поиске открыты все семейства с совпадениями. Так же устроено оборудование: нагреватели, охладители, источники тока, посуда и «Вимірювальні прилади» (весы — на чём взвешивать; динамометр открывает панель, где подвешивают тело) сгруппированы по категориям каталога (побутові / лабораторні), открыта группа выбранного прибора.

### Теплообмен: смешивание и тепловой баланс

Металлы и сплавы (алюминий, медь, железо, сталь, латунь, олово — плотность и теплоёмкость из источников) стоят на полке как **тела, которые кладут в жидкость** (`solid.metal`); в «Нагріти до» и «Розплавити» они (и соль, и стекло) бывают и **образцом сам по себе** — см. «Нагрев и плавление сухих веществ». Брусок — отдельное тело-кубик, омываемое водой со всех сторон; по умолчанию его берут «з окропу», 100 °C. Горячая вода, налитая в холодную, смешивается сразу по уравнению теплового баланса.

Операция «Дочекатися рівноваги» ([settle.ts](../src/scenarios/operations/settle.ts)) — без прибора: ждёт, пока всё, что положили в жидкость, придёт к её температуре (±0,3 K — точность школьного термометра), а стенки посуды догонят воду (меньше десятой части разницы «вода − комната»: стекло устанавливается на ≈ 5 %, сталь на ≈ 2,5 %). Если ничего не положили — Профессор подсказывает, что сделать. Доска пишет формулу смеси (сразу, с числами), `Q = c·m·Δt` для каждого тела и в конце — сам баланс `c₁m₁(t₁ − θ) = c₂m₂(θ − t₂)`: отданное и полученное, разница ушла в посуду и воздух. Скачок температуры при доливании — смешивание, а не нагрев: в `Δt` он не входит.

**Калориметр** — алюминиевый стаканчик во внешнем стакане с воздушным промежутком (`VesselSpec.jacket`): теплота уходит наружу через слой неподвижного воздуха (его теплопроводность — из источников), затем в комнату; размеры и массы — оценки, школьные калориметры разные. На плиту и над огнём его не ставят — греют только изнутри кипятильником. В нём смешивание 50 → 48,5 °C (остаток забирает сам стаканчик), а за 10 минут с крышкой вода остывает втрое меньше, чем в стакане.

Готовые опыты могут класть что-то в посуду до старта (`Preset.setup`): «Змішуємо гарячу й холодну воду» (ровно 50 °C сразу после смешивания — и 47 °C в равновесии со стаканом) и «Алюміній чи мідь» (ответ сравнивает с прогоном «в уме» медного бруска той же массы). Сессия теперь сохраняет снимок состояния сразу после команды, меняющей вещество, — начальная температура бруска точная.

### Нагрев и плавление сухих веществ: излучение, пламя, предел посуды

Твёрдое вещество (соль, металл, стекло — не дерево: оно обугливается, данных нет; `isDrySample`) может быть образцом: операции с `Operation.solids` («Нагріти до», «Розплавити») принимают его, на полке его карточка тогда выбирает образец (количество — в граммах), а не готовит «додати в рідину». У веществ, твёрдых при комнатной температуре, с данными о плавлении есть `SubstanceItem.melt` (точка, теплота плавления, теплоёмкость и плотность расплава — из источников: NIST-JANAF, Википедия) и тот же переход в `freezing` «со стороны твёрдого»; `liquidHeat(sub)` — теплоёмкость жидкого состояния. Сухое содержимое посуды — одно тело без воды (соль — не рассол), стенка → содержимое через точки касания (`CONVECTION.dryContact`, оценка). Новые данные: олово (232 °C, «полиця» на графике), фарфор, порцеляновий тигель (паспорт 30 мл: 26 г, стенка 2 мм, до 1150 °C), муфельная печь (до 1100 °C; как «окружение при заданной температуре», `CoolerSpec.hot`; её собственный разогрев не моделируется).

Три вещи, без которых раскалённое врёт:
- **Излучение** (`ThermalLinkParams.radiation`, [links.ts](../src/domains/thermal/links.ts)): εσA(T⁴ − T⁴) сверх того, что уже сидит в h неподвижного воздуха (линеаризация при 20 °C), — поэтому при комнатной температуре добавка ≈ 0, и все прежние опыты не изменились, а у тигля при 800 °C это главная потеря. Коэффициенты излучения — по материалам (`SURFACES`), излучают внешние стенки посуды и диск электроплиты (иначе он грелся бы под сухой кастрюлей бесконечно).
- **Пламя не горячее себя** (`BurnerParams.flame`, `HeaterSpec.flameTemperature`): доля мощности, которую берёт тело в пламени, падает линейно от 100 °C (до 100 °C — вся измеренная доля, она мерилась на воде) до нуля при температуре пламени (газ ≈ 1500 °C, спиртовка — оценка 1200 °C); не взятое уходит в комнату.
- **Предел посуды** (`SURFACES[material].limit`): алюминий и медь — их температура плавления, стекло — 500 °C (боросиликат), фарфор — 1150 °C. `labGoalReached` останавливает опыт, когда стенка дошла до предела; статус `vessel-fails` («Посуд не витримав… а тоді алюміній плавиться і дно прогорає»), прогноз видит это заранее (`ahead`). Индукционная плита отключается при перегреве посуды (`vesselCutoff`, оценка 270 °C — термостат на стенке), кипятильник в сухом веществе не включается (предупреждение).

**Растворение — одно правило** ([dissolve.ts](../src/domains/thermal/dissolve.ts)), не зашитое в опыты: когда в `thermal.add` встречаются вода, рассол и соль — в любом порядке и виде (соль в воду, вода на сухую соль, «замороженный» кусок соли, горячий, рассол в воду), — они становятся одним телом вода + соль; модель раствора решает, сколько растворено, остаток лежит кристаллами и сам растворяется дальше при нагреве или доливании (равновесие пересчитывается каждый шаг). Вещество, твёрдое при комнатной температуре, «замороженным» не бывает (флаг игнорируется). Не растворяются металл, соль в масле, кусок льда в чистой воде (он плавает и тает). Профессор после любого добавления (и в свободном режиме) говорит, сколько растворилось и что поможет: нагреть (если при 100 °C растворится всё) или долить воды. Плавление и таяние отдельного правила не требуют: решатель плавит любое тело с фазовыми данными по его энергии. На доске Δt пишется с точностью 0,1 °C — иначе произведение не сходится (864 · 0,1 · 30 ≠ 2 620). Что выходит: 100 г соли в кастрюле до 100 °C — за 1,5–2 мин, дно ≈ 200 °C, ничего не прогорает; расплавить соль на газу нельзя — ≈ 460–530 °C и стоп (подсказка: муфельная печь, проверена расчётом); в печи при 900 °C в тигле — ≈ 20–30 мин; алюминиевая кастрюля в печи прогорает раньше, чем соль расплавится; олово над спиртовкой плавится ≈ 20 мин с «полицей» 232 °C; алюминий в тигле над газовым пальником — ≈ 18 мин. Готовые опыты 8 класса: «Плавлення олова» и «Чи розплавиться сіль у каструлі?» (на плите — нет; шаг `fresh` с `set` пересыпает в тигель, следующий — в печь).

На сцене — тигель в фарфоровом треугольнике на треноге, муфельная печь с раскалённым нутром, сухое содержимое своим цветом (расплав светится), и красное каление стенок выше ≈ 470 °C (`incandescent`).

### Механический стенд (7 класс): пружина, трение, давление

[bench.ts](../src/scenarios/bench.ts): измерения рядом с посудой, как в лабораторных работах учебника. `lab.stretch` — тягарці по 100 г на пружине (25 Н/м из набора 3B Scientific), длина по линейке с миллиметровыми делениями; `lab.pull` — сосновый брусок 12 × 6 × 4 см (масса из плотности дерева) тянут по дошці динамометром, μ дерева по дереву 0,25 из таблицы учебника; `lab.edge` — ребра бруска линейкой. Шаг протокола `bench` несёт саму команду; его текст и кнопка — в `BENCH_TEXT`. `lab.balance` — важільні терези с набором важків по ряду (1; 2; 2; 5) × 10ⁿ из OIML R 111 (100 г … 10 мг): тело, посудина с содержимым или пустая посудина (до того как налили); показание — сумма важків, которыми терези зрівноважено. Доска пишет k = F/x, μ = F/N, p = P/S по каждой грани, набор важків, массу жидкости как разность зважувань и её густину по поділках мензурки. Опыт с `bench` рисует на столе стенд вместо посуды ([bench.ts](../web/graphics/scene/bench.ts)): штатив с пружиной, тягарцями и линейкой, брусок на доске с горизонтальным динамометром, брусок с линейкой у измеряемого ребра.

### Движение приборов: общие правила

Показание прибора не появляется мгновенно — прибор приходит к нему ([motion.ts](../web/motion.ts)). Подвижная часть — канал с одним из законов: затухающие колебания около цели (коромысло, пружина с грузом, стрелка: период, затухание, упоры), плавное приближение без перелёта (термометр) или равномерное движение (брусок, который тянут). Процедура — шаги во времени, меняющие цели каналов (важки кладут по одному, лишний снимают). Движение закончено, когда процедура пройдена и все каналы успокоились; тогда сцена шлёт `instrument-settled`, и только после этого Профессор называет показание, доска его записывает, а ответ опыта считается. Пока прибор движется, Профессор говорит, что происходит (`BUSY`). Прибор лишь описывает себя ([bench-motion.ts](../web/graphics/scene/bench-motion.ts)): что движется, по какому закону, с какой процедурой; числа — из физики, где это возможно (период пружины с грузом T = 2π√(m/k) из её жёсткости и массы важків), иначе это параметры рисунка. При «уменьшить движение» прибор сразу рисуется в покое. Новый прибор получает движение, описав себя здесь же.

### Плотность и плавание (механика, 7 класс)

Маленький домен [src/domains/mechanics/](../src/domains/mechanics/): формулы `ρ = m/V`, `P = m·g`, `F_A = ρ·g·V` и доля погружения `ρ_т/ρ_р`, закон Архимеда с историей (Wikidata, «Про плаваючі тіла», бл. 246 р. до н. е.), `g` — стандартное (CODATA). Формулы привязаны к цитатам обеих программ (7 класс). Тела в жидкости ([measuring.ts](../src/scenarios/measuring.ts)) плавают или тонут по плотности: лёд — на ≈ 92 % под водой, сосна — наполовину, металлы на дне. Уровень по делениям считает жидкость, лёд и тела так, как их видит мензурка: плавающее тело вытесняет свою массу жидкости, утонувшее — свой объём; поэтому растаявший лёд уровень не меняет — это проверяет тест.

Измерения — команды-измерения, как взвешивание: `lab.read-level` (мерный цилиндр 100 мл с делением 1 мл; у стакана грубые деления по 25 мл) и `lab.hang` (динамометр 5 Н с делением 0,1 Н: тело в воздухе — `P = m·g`, в жидкости — меньше на архимедову силу; плавающее тело оставляет пружину свободной). Показания несут числа, из которых получены (`MeasurementRecord.inputs`), поэтому доска пишет `V = V₂ − V₁`, `m = m₂ − m₁`, `ρ = m/V` и архимедову силу двумя способами — по показаниям (`P − P′`) и по закону (`ρ·g·V`). На сцене — плавающие тела у поверхности, метка уровня, динамометр с телом над посудой или в жидкости. Новые тела на полке: сосновый брусок и стеклянный шарик (плотности из источников). Мензурку не нагревают.

**Пошаговые процедуры**: так идёт **каждый** готовый опыт (`guidedPlan`: что кладут до старта, затем само действие, затем остальной план — у шагов-действий значок по их сути: 🔥 нагрев, ❄️ холод, ⚡ ток, ⏳ ожидание; жидкость «доливают» 🫗); измерительные опыты 7 класса заданы так прямо (`Preset.guided`): измерительный опыт ведёт Профессор — без «Старта», каждый шаг плана — кнопка под сценой («Крок 2 з 5: подивись на поділки…»), опускание тела — отдельный шаг (брусок падает в мензурку, вода плавно поднимается). Каждое показание сначала записывается на доску, как в тетради (`m₁ = …`, `V₁ = …`), затем выводы (`m = m₂ − m₁`, `V = V₂ − V₁`, `ρ = m/V`); когда всё измерено, приборы отодвигаются — доску видно целиком. В протоколе до начала операции нет строки «…— чекає на старт»: операция стоит в плане на своём месте, а над ним — только уже сделанное (добавленное, измеренное), строкой «Вимірювання»; с началом операции эти замеры становятся частью её строки. Прогноз, если он есть, предлагается над первым шагом; ответ и вердикт — в той же панели в конце. «Що це за метал?» заканчивается **таблицей густин** (`choicesAt: 'end'`, `choiceTable: 'density'`): все твёрдые тела полки по плотности, ученик сам находит своё «Це він!», верный ответ — ближайшая к измеренной плотность. Шаг плана может быть и операцией («⏳ Чекати, поки лід розтане»: своё название и скорость, медленнее — чтобы успеть увидеть); пока она идёт, панель говорит «стеж за посудом». Опыт со льдом идёт так: уровень воды → кубик падает и всплывает → уровень → ждём, пока растает → уровень; на доске `ΔV = V₃ − V₂ = 0`. Всё, что происходит, показано постепенно: тающий кубик уменьшается и бледнеет, соль опускается крупинками и растворяется облачком, вода поднимается плавно. Звуки ([web/sounds/](../web/sounds/index.ts)) синтезируются в браузере (Web Audio, без файлов): «бульк», когда тело касается воды (ниже — у тела побольше), тихое шипение, пока растворяется соль; гул блока питания, пока идёт ток (электролиз, нагрев током), и на мгновение, когда в цепи замыкают ключ (`hum`: трансформатор гудит на 100 Гц — сердечник сжимается дважды за период сети 50 Гц, — немного 50 Гц и «жужжание» гармоник до ~900 Гц, чтобы его было слышно и в маленьких динамиках; громче при большем токе); кнопка 🔊/🔇 в шапке, выбор запоминается. Профессор «бормочет» каждую новую реплику (длинную — постранично: видимую страницу облачка, следующую — когда её перелистывают «Далі» / «Назад»; слог примерно на три буквы, не дольше ≈ 1,6 с; в конце вопроса голос поднимается), и у него двигается рот; голос выбирают в шапке: мультяшний професор (по умолчанию; подобран по спектрограмме к мультяшному голосу, который понравился автору, — запись не используется, у неё нет лицензии: тон 120–195 Гц (чуть ниже образца) скачет от слога к слогу, но за фразу не растёт (у образца рос — фраза за фразой это звучало как голос, который всё время лезет вверх), провал на 2–2,5 кГц, яркая полоса около 4 кГц; нарочно тарабарщина: один источник на всю фразу, слоги перетекают друг в друга, «рот» блуждает между гласными даже внутри слога, слог ≈ 0,2 с, слоги неровные, изгиб тона у каждого свой, лёгкая хрипотца), озвучення (встроенный голос браузера читает реплику на языке страницы; если такого голоса нет — мультяшний) или мовчки; консоль `voice`. Ничего не звучит до первого клика или клавиши — браузер иначе сыграл бы всё накопленное разом. Когда опыт закончен (ничего не осталось в плане), под сценой появляется «🔄 Новий дослід»: губка проходит по доске и стирает записи, затем всё ставится заново с начала (готовый опыт — со всеми шагами). «↺ Спочатку» делает то же, что «🔄 Новий дослід»: губка стирает доску, готовый опыт начинается заново из того, каким его выбрали (`presetGiven`: шаги по пути меняют параметры — каструля без кришки, ожидание таяния). Под сценой сначала итоги словами (`#messages`, `#offer`), потом ручка и табло, график, энергия. На полке описание вещества (что оно такое и что о нём лишь оценка, безопасность) стоит сразу под заголовком «Речовина», до карточек с числами; настройки выбранного предмета (количество, температура, мощность, объём) — сразу под его семейством, а не после всех семейств. Доска не стирается между шагами: строки уже сделанных шагов остаются, новый шаг дописывает свои ниже (на доске помещается до 12 строк в две колонки; стирает её только «Новий дослід»). Если шаги отличаются лишь крышкой, к заголовку строки добавляется «з кришкою» / «без кришки». Шаг `{ kind: 'fresh', lid? }` ставит опыт заново с чистой посудой (можно поменять крышку): так «Навіщо каструлі кришка?» кипятит воду дважды — с крышкой и без, ответ сравнивает настоящие времена двух прогонов, а строки протокола подписаны «з кришкою» / «без кришки». Пар на сцене — клубы (`steamPuffs`): с крышкой выбиваются из-под её краёв, без крышки поднимаются над всей водой; перегретое масло дымит серым (`smoke`). Группа пара называется `sc-vapour`: прежний id `sc-steam` совпадал с градиентом в `<defs>`, и пар не включался никогда. Неизвестный металл — медь: ближайший сосед в таблице (латунь) отличается на 4,5 %, больше погрешности мензурки на 20 мл; железо и сталь (7874 / 7850) так не различить.

Готовые опыты 7 класса: «Чи зміниться рівень води, коли лід розтане?», «Що це за метал?» (брусок без подписи: ученик взвешивает и смотрит на деления, ответ — по его же показаниям), «Де архімедова сила більша?» (пресная и солёная вода). Шаги-измерения плана останавливаются на показании; если план закончился измерением, вопрос получает ответ сразу. Ответы готовых опытов получают все показания опыта (`PresetRun.readings`).

### Протокол: опыт как цепочка шагов

Один образец, несколько шагов: «закипятить → досыпать соль → выпарить досуха», «закипятить на плите → охладить в холодильнике → заморозить в морозилке» ([protocol.ts](../src/scenarios/protocol.ts)). Шаг — операция со своим прибором или добавление вещества. Между операциями посуда «переезжает»: `configureStep` берёт свежую установку для нового шага и переносит в неё всё вещество как есть (температура, состав, лёд, добавленное) и комнату; приборы — новые, но та же плита остаётся горячей. Каждый шаг — отдельный прогон со своим итогом, балансом энергии и разбором; время в итогах считается от начала шага. В конце каждого шага Профессор называет его результат (`stepOutcome` в [thermal-lab.ts](../src/scenarios/thermal-lab.ts)): глагол операции, содержимое по имени, время, первое предложение примечания операции (общая температура, средний ток) и что стало с кристаллами (`crystalNote`: растворились, выпали — или не выпали, и раствор пересыщен); потом — что дальше по плану. Кристаллик, брошенный в пересыщенный раствор, Профессор называет затравкой.

Если цель так не достичь, лаборатория не просто сообщает об этом, а **предлагает остановиться или изменить условия** ([lab-fixes.ts](../src/scenarios/lab-fixes.ts)). Операция говорит, чего ей не хватает (`needs`: окружение холоднее X, другая цель, нагрев), а лаборатория подбирает из каталога конкретные варианты — «морозилка −22 °C» для морской воды при −18 °C — и оставляет только те, при которых цель достижима. Если нагрев «застрял» (потери сравнялись с мощностью), варианты — ручка на максимум, крышка, мощнее модель, меньше вещества, другой нагреватель — проверяются прогоном «в уме». Выбранный вариант продолжает опыт следующим шагом с тем же образцом. «Нет продвижения» — одна общая проверка (`noProgress`): медленное испарение считается продвижением только для «випарити досуха».

На странице протокол растёт по ходу опыта: шаг закончился → выбираешь слева другую операцию или прибор → «Продовжити». Смена операции посреди шага закрывает его и начинает следующий; смена вещества или посуды — новый опыт. Справа — журнал шагов.

### Записи: сохранить цепочку и повторить

Опыт можно записать ([recording.ts](../src/scenarios/recording.ts)): для каждого шага — его настройки, все команды с точной секундой от начала шага (ручка, досыпанная соль; сделанное в паузе после шага относится к этой паузе) и как шаг закончился (`'goal'` — дошёл до цели, число — остановлен через столько секунд). Физика детерминирована, поэтому повтор (`replayStep` / `replayRecording`) даёт тот же результат до последнего знака: первый шаг — со свежей установки, каждый следующий — из состояния, где закончился предыдущий (`configureStep`). Запись — JSON (`format: 'spark-recording'`, `version: 1`); `parseRecording` проверяет чужой файл по каталогам, прежде чем запускать.

На странице: «💾 Зберегти дослід» в протоколе, список «Мої записи» (▶ повтор шаг за шагом с анимацией, ⬇ файл, 🗑, ⬆ загрузить файл), хранение в `localStorage` (`spark.recordings`). В консоли — `save <name>`, `records`, `replay <n>`. Любой собственный выбор пользователя прерывает повтор.

### Взвешивание: измерение как команда

Весы — прибор с паспортом ([scales.ts](../src/equipment/scales.ts)): кухонные (5 кг, деление 1 г) и лабораторные (620 г, 0,01 г), числа — из листингов производителей. Взвешивание ([weighing.ts](../src/scenarios/weighing.ts)) — команда `lab.weigh` вида `measurement`: состояние не меняет, а показание (масса посуды со всем содержимым, округлённая до деления; выше предела — «перегрузка») кладёт в трассу как `MeasurementRecord`. Поэтому взвешивания попадают в журнал шага, в протокол, в записи и повторяются вместе с ними. Масса считается по телам вещества: посуда, крышка, образец (лёд и соль внутри), добавленные куски — испарившаяся и выкипевшая вода уходит из образца, и весы это видят. В протоколе взвешивание — шаг `{ kind: 'weigh', scale }`; на странице — кнопка «⚖ Зважити», консоль `weigh [kitchen|lab]`; на сцене посуда «переезжает» на весы с табло. Шаг, в котором время ещё не шло, при смене действия собирается заново с теми же командами (соль, взвешивание) — пустых шагов в протоколе нет.

### Вопросы с вариантами и разбор всего опыта

У готового опыта есть варианты ответа на его вопрос (`Preset.choices`) — прогноз до старта. Какой вариант верный, не записано в пресете: ответ (`PresetAnswer.correct`) выводит его из прогона модели, а тест проверяет, что прогон всегда выбирает один из вариантов. Так как верный вариант известен только после прогона, вариантов у прогноза не больше четырёх. Вопросы, на которые страница может ответить сразу (после взвешивания «куди поділися ці грами?»), берут четыре случайных варианта из пула, правильный — всегда среди них; порядок зависит от ключа вопроса и не меняется между кадрами. На неверный вариант Профессор объясняет, почему это не так, и предлагает попробовать ещё.

Подробный разбор («Поясни») начинается с хода опыта ([lab-course.ts](../src/scenarios/lab-course.ts)): каждый шаг с действиями до, во время и после него (взвешивания, досыпанное, ручка) и итогом — температура, лёд, сколько воды ушло в воздух, масса содержимого. Затем — последний шаг подробно, а предыдущие шаги — свёрнутыми полными разборами.

### Доска над столом

На стене сцены висит доска ([lab-board.ts](../src/scenarios/lab-board.ts)) — от верха до столешницы и почти во всю ширину: стена рисунка прозрачна, доска висит под ним, а стол, приборы и Профессор стоят перед ней. Доска не выдвигается: кнопка на краю стола «👀 Подивитися на дошку» уменьшает всё, что стоит на столе, и отодвигает к правому краю, а Профессор отступает влево, становится боком (рисунок в профиль, руки за спиной) и читает; пока он читает, его реплика спрятана и сценки скуки не начинаются. «↩ Повернутися до досліду» возвращает всё на место. На доске — формулы того, что происходит в текущем шаге. Шаг делится на фазы по записанным состояниям — всё твёрдое, всё жидкое, и то и другое — и каждая фаза получает строку в порядке, в каком случилась: `Q = c·m·Δt` (нагрев/охлаждение льда или жидкости), `Q = λ·m` (плавление/кристаллизация), `Q = L·m` (кипение, от 0,1 г выкипевшего), `I = U/R` и `Q = I²·R·t` (ток), `m = m₁ + m₂` (последнее взвешивание), а если взвешен раствор — `w = m(речовини) / m(розчину)` для каждого растворённого вещества (кристаллы на дне в массу раствора не входят). Пока фаза идёт, на доске только формула; числа этого прогона дописываются, когда фаза закончилась («формула отработала») — тоже мелом. Константы — из моделей веществ (лёд в солёной воде — это замёрзшая вода, его данные берутся у воды). Новый шаг — чистая доска.

Доска добавляет и энергию прибора: в конце шага с нагревателем — `E = P·t` (сколько отдал нагреватель; P — средняя мощность за шаг) и `η = Q/E` (какая доля досталась самому веществу — то же число, что в балансе энергии разбора). Пишет её шрифт Caveat (SIL OFL 1.1, файлы и лицензия в `web/fonts/caveat/`, сборка вкладывает их в страницу). Пока Профессор читает, он ведёт головой вдоль строк и кивает, когда дописываются числа. Если доска чистая, через 3 секунды начинается сценка: Профессор бормочет через плечо («Так-так… Ану, що тут у нас…»), оборачивается к классу («Схоже, тут нічого немає, колего!?») и подсказывает начать дослід — один раз за каждый взгляд на доску.

Чтобы сцене хватило места, она выше (больше стены сверху; предметы того же размера — меняется только видимая область рисунка), а график сворачивается: пока идёт опыт, видны ручка и плитки показаний; когда шаг закончился, график разворачивается и мигает 👇 — «результаты внизу». Обе боковые панели сворачиваются кнопкой в собственной строке заголовка в узкую полоску вровень с другими колонками.

### «До речі!..» — газета Профессора

После двух сценок скуки Профессор восклицает «До речі!..», и открывается страница старой газеты ([newspaper.ts](../web/newspaper.ts)): кто из учёных или изобретателей родился в этот день (лента Википедии «цей день», отбор по описанию), или справка о веществе или учёном самой лаборатории — темы берутся по Wikidata-идентификаторам компонентов и людей из истории законов. Текст каждый раз загружается живьём из Википедии (на языке страницы) и нигде не сохраняется; внизу — статья и лицензия (CC BY-SA 4.0). Статьи о российских и советских фигурах не показываются. В пределах визита статьи не повторяются. Без интернета — история одного из законов лаборатории (тексты Spark, даты по Wikidata). ### Растворы: состав, а не «модель на каждый раствор»

Раствор — не отдельное вещество и не отдельная модель, а тело с **составом**: вода, лёд и список растворённых компонентов, у каждого своя масса и своя часть, лежащая кристаллами (`mixture: { water, ice, solutes: [{ component, mass, crystals }] }`; суммы `salt` и `crystals` — для читателей, которым нужно только «сколько всего в воде»). Сколько угодно веществ в любых пропорциях: вода + соль + сахар, вода + глицерин. В коде нет ни одного названия раствора ([mixture.ts](../src/domains/thermal/mixture.ts)); всё следует из данных компонентов и общих законов:

1. **Сколько растворится** — растворимость самого компонента в воде по температуре (`inWater.solubilityTable`, г на 100 г воды; сахар, сода, медный купорос — из таблицы растворимостей Википедии); смешивающаяся в любых пропорциях жидкость (глицерин) не кристаллизуется. Остаток лежит кристаллами и дорастворяется сам при нагреве или доливании.
2. **Где вода начинает замерзать** — закон Благдена ΔT = K_f·Σ i·b (K_f воды 1,86 К·кг/моль в `Component.solvent`; i — число частиц: сахар 1, соль 2): лёд выделяется, остаток крепчает и замерзает холоднее — до насыщения (эвтектика выходит из тех же кривых), ниже всё твёрдое.
3. **Кипение** — закон Рауля: растворённые частицы понижают давление пара воды.
3а. **Пересыщенный раствор** — у вещества с `inWater.supersaturates` (натрий ацетат, с источником) кристаллы не появляются сами, пока в растворе нет ни одного его кристалла (`heldIn` в [mixture.ts](../src/domains/thermal/mixture.ts)): охлаждённый ниже насыщения раствор остаётся жидким (табло: «пересичений»). Затравка — его кристаллы на дне или кристаллик, брошенный в раствор (`thermal.add` сухого вещества того же компонента): раствор сразу приходит к равновесию и отдаёт теплоту кристаллизации — грелка из 20 г ацетата в 4 мл воды нагревается от 22 до ≈ 48 °C.
4. **Теплота** — сумма теплоёмкостей и теплот переходов компонентов и **теплота растворения** растворённой части (`inWater.enthalpyOfSolution`, кДж/моль, CRC: NaCl +3,88, NH₄Cl +14,78, NaOH −44,51): растворяясь, вещество забирает её у раствора или отдаёт ему, кристаллизуясь — возвращает. 20 г нашатыря охлаждают 100 мл воды с 20 до ≈ 7,7 °C, 10 г едкого натра нагревают до ≈ 46 °C; доска пишет `Q = n·ΔH`.
5. **Плотность** — сложение объёмов (приближённо).
6. **Измеренные данные пары «вещество + вода» — там, где общий закон неточен**: у соли — кривая замерзания до эвтектики −21,1 °C, плотности, проводимость (`inWater.model`); они берутся, когда соль — единственное растворённое вещество, иначе — общий закон.

Растворение — одно правило ([dissolve.ts](../src/domains/thermal/dissolve.ts)): при `thermal.add` вода, растворы и растворимые вещества — в любом порядке и виде (сахар в воду, вода на сухую соль, «замороженный» кусок, раствор в раствор) — сливаются в одно тело; энергия сохраняется (сухое вещество — то же состояние в другой точке отсчёта). Не растворяется металл, мел, графит, масло, кусок льда в чистой воде. Летучие компоненты (вода, спирт, уксус) испаряются и кипят по закону Рауля для каждого: давление пара — своё уравнение компонента или, без него, закон Клапейрона–Клаузиуса из температуры и теплоты кипения; смесь кипит там, где Σ x·γ·p(T) = 1 атм, пар уносит каждый компонент по его доле (спирт уходит первым — перегонка: 10 % спирта закипает ≈ 92 °C, спирт выкипает за минуты, температура поднимается к 100 °C), с открытой поверхности испаряется каждый по своей доле. Неидеальность пары «вещество + вода» — измеренные коэффициенты ван Лаара (`inWater.activityWithWater`; этанол — из справочника Perry’s: 40 % спирта кипит ≈ 83,5 °C, как в реальности, а идеальный закон дал бы ≈ 94 °C). Уксусная кислота — слабая, в растворе считается одной частицей. Ограничения общего закона: идеальное смешивание, законы Благдена и Рауля точны для разбавленных растворов, кристаллогидрат медного купороса считается вместе с кристаллизационной водой. Растворы на полке («морская вода», «10 %») — рецепты; заголовок и табло называют состав («Розчин мідного купоросу», «цукру 60 %»), раствор медного купороса голубой (`inWater.tint`).

## Модуль 2: электричество (ток через жидкость)

Источник постоянного тока (батарейка 9 В, USB 5 В, лабораторный блок 0–30 В — [supplies.ts](../src/equipment/supplies.ts)) и два электрода в жидкости ([src/domains/electrical/](../src/domains/electrical/)):

- **проводимость** κ берётся из моделей компонентов: раствор соли — таблица CRC (20 °C) + поправка ≈ 2 %/К; дистиллированная вода — своё малое значение; лёд и изоляторы (масло, спирт) — ноль; проводит только жидкая часть;
- **сопротивление** R = K / κ, где K = L / A — постоянная ячейки (электроды 2 × 5 см на расстоянии 3 см → 30 1/м);
- **ток** I = (U − U_разл) / (R + R_внутр), не больше предела источника; ниже напряжения разложения (вода 1,23 В, рассол 2,19 В из стандартных потенциалов) тока нет;
- **теплота Джоуля–Ленца** I²R идёт в жидкость через «ведомый» тепловой источник: электрический решатель задаёт его мощность, тепловой — разносит (фазы, кипение, баланс энергии работают как обычно); домены не импортируют друг друга;
- **закон Фарадея**: из прошедшего заряда — объёмы газов (водород и хлор из рассола, водород и кислород из воды);
- **энергия источника** = тепло жидкости + химическая энергия газов + нагрев самого источника (проверяется тестом); батарейка разряжается (550 мА·ч).

Знания домена ([catalog.ts](../src/domains/electrical/catalog.ts), [laws.ts](../src/domains/electrical/laws.ts)): опір рідини R = K/κ, закон Ома с напряжением разложения, Джоуль–Ленц P = I²R, Фарадей n = q/(zF) — с цитатами программ МОН (8 клас) и историей открытий (Ом 1827, Джоуль 1840 и Ленц 1842, Фарадей 1833–1834) с источниками. Решатель пишет trace каждой формулы; тест пересчитывает их по каталогу. `LAB_KNOWLEDGE` объединяет тепловые и электрические знания для разбора.

Операция «Пропустити струм» задаётся длительностью; в протоколе её можно чередовать с нагревом и добавлением веществ («вода на горелке → соль → ток → нагрев → снова ток»).

### Электрохимия: химия в тех же компонентах

Химические свойства живут в тех же компонентах, что и физические (`Component.electrical`): у электролиза каждого электрода — стандартный потенциал полуреакции (вода: 2H₂O/H₂ −0,8277 В, O₂/OH⁻ 0,401 В; рассол: Cl₂/Cl⁻ 1,36 В), у материала — как он ведёт себя электродом (`ElectrodeBehaviour`): графит инертен, железо и сталь отдают Fe²⁺ (E° −0,44 В), а с гидроксид-ионами от катода выпадают осадком Fe(OH)₂ (новый компонент `iron-ii-hydroxide`, данные из источников). Общее правило ([electrochem.ts](../src/domains/electrical/electrochem.ts)): на аноде побеждает более лёгкое окисление — металлический анод растворяется, если его потенциал ниже того, что дала бы жидкость (железо −0,44 В против хлора 1,36 В); напряжение разложения — разность потенциалов. Электроды выбираются на полке («Графіт» по умолчанию — как в школе; «Сталь»). Решатель накапливает продукты по Фарадею шаг за шагом (`SupplyState.made`, моли по компонентам), объяснения строятся из них. Кусок металла в растворе, ни к чему не подключённый, становится биполярным электродом: часть тока идёт через него, если поле на его длине даёт больше его собственного напряжения разложения (оценка по геометрии: доля площади электрода и длина вдоль зазора); его конец к катоду растворяется, к аноду — даёт водород, ржавеет. Металл без данных о поведении электродом (медь, алюминий…) честно называется: «реагував би, але модель поки не вміє». На сцене: графитовые электроды тёмные, стальные светлые; растворяющийся анод без пузырей; зеленоватый осадок на дне и муть. Пока не моделируется: как осадок буреет на воздухе (ржавчина), убыль массы бруска на весах, медный анод.

## Страница: сцена, полка, готовые опыты

- **Сцена** ([web/scene.ts](../web/scene.ts)) — живой SVG-рисунок того, что стоит на столе: прибор (по полю `look` в каталоге оборудования), посуда с содержимым — уровень, цвет жидкости, лёд (плавает сверху), кристаллы соли, пузыри кипения, пар, газ на электродах, облачко хлора, термометр. Сцена только читает состояние; статичная часть перестраивается при смене установки, живые детали — каждый кадр, анимации на CSS. Рядом Профессор: настроение и реплика по событию (кипит, замерзает, ток, хлор, тупик, успех, следующий шаг плана).
- **Полка** — карусель операций (по две плитки, как все карточки), карточки с рисунками: бутылки веществ с формулой, миниатюры посуды той же графикой, что и сцена, значки приборов; плитки операций с иконками (иконку называет сама операция, поле `icon`), «капли» цвета жидкости у веществ, значки посуды и приборов.
- **Графика** лежит в [web/graphics/](../web/graphics/README.md) по тому, что изображено: `icons/` — простые значки отдельными `.svg`-файлами в папках `operations/`, `vessels/`, `devices/`, `instruments/` (имя файла — то, что пишут в `icon` / `look`; новый значок — новый файл); `professor/` — Профессор анфас и в профиль и страница-превью; `scene/` — рисунки стола: посуда, приборы, измерительные приборы, тела в жидкости, цвета, система координат; `shelf/` — картинки карточек полки. То, что зависит от опыта (цвет, уровень, показания), — код; неизменное — файлы. `web/scene.ts` только собирает рисунки и двигает живые детали.
- **Только совместимое** ([choices.ts](../src/scenarios/choices.ts)): операция сама решает, с какими веществами она возможна (`accepts`: плавить можно только то, у чего есть твёрдое состояние); прибор — какую посуду можно поставить (индукция — магнитный металл, плита — плоское дно, кипятильник и электроды — по ширине горла); в «Додати» — только то, что команда добавления действительно примет (пробный прогон). `fitChoices` приводит установку в согласованное состояние после выбора. Во время опыта вещество и посуда не меняются, а действия и приборы предлагаются только совместимые с ними.
- **Справка** ([web/reference.ts](../web/reference.ts)) выезжает поверх лаборатории по кнопке «i» на карточке: паспорт (формула, молярная масса из формулы, тип), свойства по агрегатным состояниям, переходы с теплотами, поведение в воде, электричество и магнетизм, безопасность, допущения модели; у рецепта — состав со ссылками на компоненты и свойства смеси, посчитанные моделью; у оборудования — характеристики. У каждого числа — степень проверки и номер источника со ссылкой; условия измерений и примечания к данным — для уровней «поглиблений» и «експерт».
- **Консоль** ([web/console.ts](../web/console.ts)) — выезжает снизу по кнопке `>_` в левом нижнем углу, высота меняется перетаскиванием верхнего края (или стрелками) и запоминается, Esc закрывает. Команды по-английски (украинские названия команд — тихие синонимы), описания — на языке интерфейса: всё, что делается мышью (`action freeze`, `substance sea 0.2 l`, `device freezer -22`, `add salt 7 g`, `start`, `status`, `info chloride`, `preset 5`…), плюс `prof <scene>` — сыграть сценку Профессора сразу. Названия веществ и приборов понимаются на обоих языках и сокращёнными (начало слова или общая основа от 5 букв), Tab дописывает, ↑/↓ — история. Команды вызывают те же функции страницы, поэтому консоль подчиняется тем же правилам совместимости.
- **Готовые опыты** ([presets.ts](../src/scenarios/presets.ts)) — по классам и темам (8 клас: теплові та електричні явища; «Для всіх»): вопрос, установка, при необходимости — план следующих шагов, который ведёт Профессор, и формулы, чьи цитаты программы МОН показываются в карточке (`quoteHas` выбирает нужную тему). Тест прогоняет каждый опыт с планом и проверяет, чем он кончается в модели.

Проводимость раствора — по измеренным таблицам самих растворённых веществ (`inWater.conductivityTable`; соль, медный купорос, харчова сода — таблица CRC), каждое при своей доле в растворе; при нескольких — сумма (приближение). Электролиз раствора — из данных растворённых веществ (`inWater.electrolysis`): у медного купороса на катоде медь (Cu²⁺/Cu 0,337 В), на аноде кислород (1,229 В); при нескольких веществах катод берёт самое лёгкое восстановление (наибольший потенциал), анод — газ галогена, если он есть (хлор раньше кислорода из‑за перенапряжения кислорода), иначе первое; без данных — электролиз самой воды. Металл, осевший на катоде, — налёт (катод на сцене медный), а не осадок. Готовый опыт «Що з’явиться на катоді?» — ровно Oxford Chemistry RP 1. Пока не моделируется: как раствор беднеет ионами меди и становится кислым.

### Условия готового опыта: что можно менять

Готовый опыт может объявить, что в нём можно менять до начала (`Preset.vary`): количество, температуру, материал из короткого списка — в пределах, которые держат опыт в его рамках (в опыте с кристаллами купороса столько, чтобы при 20 °C что-то лежало на дне, а при нагреве всё растворилось). Опыт строится из значений (`withValues`): посуда, шаги, текст вопроса и варианты ответа (у смешивания «рівно 42,5 °C» — из теплового баланса при выбранных количествах); значения вне рамок заменяются умолчаниями. Ответ, как всегда, считается из прогона. Под сценой — строка «Умови:» с этими ручками и «↺» (вернуть как в опыте); после первого шага её нет: между шагами условия не меняются. Тест прогоняет каждый такой опыт на краях всех диапазонов и на каждом варианте. Что меняется: пружина из набора, жидкость, кристаллы, металл, количества при смешивании; резистор из набора (3, 5 и 6 Ом; в «Опір провідника» — № 1–3 без номинала: «опір невідомий — його й знайдемо») и напряжения источника («1,5 · 3 · 4,5 В», «1 · 2 · 3 · 4 В», «2 · 4 · 6 В» — каждая пара укладывается в приборы: не больше 6 В / 3,1 Ом ≈ 1,9 А при амперметре на 2 А, 6 В при вольтметре на 6 В; в каждом наборе есть удвоение — для «удвічі більша напруга» потужності) в опытах про опір и потужність — тест перебирает все их сочетания; опір «той самий», если первое и последнее R расходятся не больше, чем позволяют полделения амперметра и вольтметра относительно их показаний (при 1 В на 3 Ом деление 0,05 А — уже 8 %); число тягарців на бруске на похилій площині (1–3, они и нарисованы); вода (100–200 г: стакан 250 мл с кип’ятильником) в ККД нагрівника и питомій теплоємності води; температура льда (−20…−5 °C); время тока (10/20/30 хв) в електрохімічному еквіваленті; напряжение источника в последовательном (2/4/6 В: 6,1 Ом — ≈ 1 А) и параллельном соединении (1–2,5 В: ≈ 1,33 Ом, 3 В — уже больше 2 А амперметра); сколько оборотов (10/20) и колебаний (10/20/30) засекать — чем больше, тем меньше доля ошибки секундомера; величина кубика льда (5/10/20 г — помещается в мензурку на 100 мл с 70 мл воды); высота верхнего конца жолоба (5/10/15 см, так и нарисован). Без условий — «Умова рівноваги важеля» (её четыре навески и есть опыт) и «Коли тіло тоне» (три порции песка подобраны под три исхода). Не меняется то, чего не выдержат приборы: стальной брусок того же размера перегрузил бы динамометр 5 Н, а металлы для гідростатичного зважування слишком близки по плотности для его поділки 0,1 Н.

### Программы у готовых опытов

У карточки готового опыта — метки программ, в которые он входит ([preset-programs.ts](../src/scenarios/preset-programs.ts)): из цитат программ при формулах опыта (НУШ, МОН 2017 — класс и точная формулировка) и из `Preset.programs` — то, что формулами не выражается (обязательная практическая работа Oxford AQA International GCSE, с номером). `match: 'related'` («≈») — та же идея на другом веществе (кривая охлаждения стеариновой кислоты — наша вода в морозилке). Точная формулировка — во всплывающей подсказке. Программы — в `CURRICULA` с коротким названием для меток; каждая со ссылкой на свой документ. Метка может назвать и тему программы (`topic`), и место в учебнике (`textbook`: источник и «§ 34, лабораторна робота № 9, с. 243») — карточка пишет их под меткой. Школы работают по разным программам и учебникам, поэтому опыт отмечает все программы, куда он подходит: НУШ (Головко и Кремінський — у второй пронумерованный перечень из 10 лабораторных работ на класс, учебник Бар’яхтара идёт по ней), МОН 2017, Oxford AQA, химия Григоровича.

### Пустой стол

Пока не выбран опыт и ничего не взято с полки (не начат опыт, не выбрана карточка «Пісочниці» — даже уже отмеченная, — не проиграна запись), стол пуст (`tableSet` в main.ts, класс `bare` у сцены и `table-bare` у страницы): ни посуды, ни прибора, ни термометра; спрятаны «Старт», весы, ручка, показания, график, протокол шага и «Додати під час досліду». Профессор говорит: «Стіл порожній. Обери дослід ліворуч — або збери свій у «Пісочниці»». Параметры песочницы по умолчанию остаются — они появляются с первым выбором.

Переход между вкладками «Досліди» и «Пісочниця» очищает стол (`clearTable`): опыт сброшен, параметры песочницы — как при запуске (`SANDBOX_START`), отчёт и ряд выбора закрыты, адрес — корень. Клик по уже открытой вкладке ничего не трогает.

### Выбор над столом

Вход в «Пісочницю» сразу открывает над столом выбор действия, и стол собирается по одной вещи ([chooser.ts](../web/chooser.ts), «choosing over the table» в main.ts): над доской ряд картинок — средняя крупно, соседние мелко по бокам; листают стрелки, свайп, клавиши ← → или клик по боковой. Этапы: дія → прилад (нагреватель / охлаждение / источник тока / «просто в кімнаті») → посуд (каждый в каждом своём материале: «Каструля (алюміній)» — ставится сразу, одним выбором) → речовина (только то, что станет образцом). Выбранное летит на своё место на столе (`fly`: место берётся у сцены, `scene.rectOf`), бутылка над посудиной наклоняется и выливается, уровень поднимается. Пока вещь выбирается, её на столе нет (`away` у сцены, жидкость — уровень 0). Во время опыта посуда и содержимое остаются: предлагаются только дія и прилад. Действие, выбранное плиткой на полке, начинает с прибора. ✕ закрывает ряд — всё выбранное остаётся на столе.

Изменить потом: кнопка «✎ Змінити» на сцене открывает ряд «Що змінити?» — дія, прилад, посуд, матеріал, речовина такими, какие они сейчас; выбранное меняется одно (дія ведёт к прибору). Клик по прибору или посуде на столе открывает их замену сразу (слой доски лежит поверх рисунка, поэтому вещь под курсором ищется по её рамке). На пустом столе та же кнопка — «🛠 Зібрати дослід».

Кнопка «➕ Додати» на сцене — то же для добавления по ходу опыта: всё, что сейчас можно добавить (сухая проба команды `thermal.add`), с порцией — у выбранного в панели «Додати» её настройки, у другого обычные (`addDefaults`); жидкость и порошок наливаются/насыпаются, брусок и лёд падают. Полка и панель «Додати» работают как раньше: полка и ряд берут варианты из одних функций (`deviceChoices`, `vesselChoices`, `substanceChoices`), карточка с полки закрывает ряд.

### Порядок опытов — как в программе

Опыты идут в том порядке, в каком их проходят по программе (`PRESET_ORDER` в [presets.ts](../src/scenarios/presets.ts); `PRESETS` отсортирован по нему, тест требует, чтобы там был каждый опыт ровно раз — новый опыт ставят на его место). По классам, темы по очереди, внутри темы — по порядку содержания Головко, ЛР Кремінського — по номерам (в 7 классе обе программы идут одинаково: рух → взаємодія → тиск → робота й енергія). Опыт нескольких классов стоит там, куда его ставит первый (рычаг — последний в 7 классе по Головко, первый в 8-м как ЛР № 1 Кремінського). Заголовки тем в списке — темы программ: «Механічний рух», «Взаємодія тіл. Сила», «Тиск твердих тіл, рідин і газів», «Механічна робота. Механічна енергія», «Теплові явища», «Електричні явища», в 9 классе — «Електричний струм у різних середовищах», «Магнітні та електромагнітні явища». Класс опыта дают его собственные ссылки на программы и главная (первая) формула; вспомогательная формула класс не добавляет (P = A/t у нагревателя — механика 7 класса, но опыт остаётся в 8-м).

### Левая панель: «Досліди» и «Пісочниця»

Левая панель — две вкладки (выбор запоминается). «Досліди» — готовые опыты: сначала предмет (Фізика, Хімія), потом класс или «Для всіх», внутри — темы. Предмет опыта — не поле опыта, а следствие его программ: у каждой программы в `CURRICULA` есть `subject`, опыт стоит под каждым предметом, в программе которого он есть как есть (не «≈»), — электролиз и в физике, и в химии (`presetSubjects`). Класс внутри предмета — по программе этого предмета (`presetGradeIn`): соль на дорогах — физика 8 класса, химия растворов 9-го. Поиск ищет по всем опытам сразу и подписывает предмет и класс. В узкой панели вопрос обрезан до трёх строк, темы программ и цитата — только у выбранного опыта (у остальных — в подсказках меток). «Пісочниця» — прежняя полка: операция, прибор, вещество, посуда. На телефоне панель стоит под сценой, к опытам ведёт кнопка «Досліди ↓» в шапке.

### Электрическая цепь (8 класс, ЛР № 6)

[circuit-bench.ts](../src/scenarios/circuit-bench.ts): `lab.circuit` — регулируемый источник, ключ, резистор школьного набора, амперметр последовательно (свой малый опор), вольтметр параллельно резистору; одно измерение даёт два показания (величины `current` и `voltage`), каждое округлено до деления прибора. Пределы, цены делений, опор амперметра и резистор — оценки (марка приборов не задана). Доска пишет показания и R = U / I. `lab.pair` — два резистора (2 и 4 Ом, оценки) последовательно или параллельно; амперметр стоит там, где меряют (в общей цепи или в ветви, со своим опором), вольтметр — на одном резисторе или на обоих; доска после трёх замеров пишет U = U₁ + U₂ или I = I₁ + I₂ с измеренным итогом. Законы соединений — со ссылкой на законы Кирхгофа (1845).

### Рычаг и наклонная плоскость (8 класс, ЛР № 1–2)

[lever-bench.ts](../src/scenarios/lever-bench.ts): `lab.lever` — рычаг-линейка на оси, отверстия через 5 см (оценка), тягарцы по 100 г с обеих сторон (равновесие или перевес) или динамометр справа: он показывает F₂ = F₁·l₁/l₂ с точностью своей шкалы; доска пишет моменты M₁ и M₂. `lab.slope` — деревянная доска лабораторной по трению, один конец поднят на штативе: F = P·(sin α + μ·cos α) с μ дерева по дереву из учебника; доска пишет Aк = P·h, Aп = F·l, η. На доске всё после «_» в формуле — нижний индекс.

### Электрохимический эквивалент (9 класс, ЛР № 3)

Медные электроды (у меди теперь есть стандартный потенциал Cu²⁺/Cu): в медном купоросе медный анод растворяется, на катоде оседает медь, газов нет — напряжение разложения около нуля. Команда `lab.cathode` ([electrode-bench.ts](../src/scenarios/electrode-bench.ts)) — катод вынули, высушили, взвесили на лабораторных весах: пластина (толщина — оценка, она сокращается в m₂ − m₁) плюс осевший металл из закона Фарадея; показание несёт заряд и время шага, так что доска пишет Δm = m₂ − m₁ и k = Δm / (I·t). На сцене катод при взвешивании исчезает из стакана и лежит на лабораторных весах между стаканом и блоком питания (`SceneView.scale.load = 'cathode'`, `plateSvg`), на дисплее — его масса; Профессор говорит её, а во второй раз — на сколько катод потяжелел. Опыт может стоять в нескольких классах одного предмета (`presetGradesIn`): электролиз — 8 класс у Головко и 9 у Кремінського.

### Протокол: назад к концу шага

Каждая законченная строка протокола — шаг, взвешивание, отсчёт по мензурке, измерение на стенде — помнит, как в этот момент выглядела сцена: тот самый `SceneView` (приборы, их показания, доска, реплика Профессора), снятый, когда строка стала последней сделанной и прибор успокоился (`liveRowKey`). Касание строки показывает его снова, над сценой — полоса «Так було після кроку…» и «↩ До досліду»; стол возвращается из режима чтения доски. Пока прибор идёт к показанию, следующий шаг ждёт: показание фиксируется таким, каким его прочли. Новый опыт стирает снимки. Когда готовый опыт получил ответ, ручка и плитки показаний прячутся.

### Сноски на термины и «Довідник»

Термины — в [src/knowledge/glossary.ts](../src/knowledge/glossary.ts): название и определение на каждом языке и основы слова, по которым термин узнаётся в любой форме («катод» → катоді, катодом; основа с «=» — только целое слово). [web/terms.ts](../web/terms.ts) подчёркивает первое упоминание термина в каждом блоке текста (объяснения, реплики Профессора, справка, описания на полке); касание или наведение показывает карточку со ссылкой на термин в глосарии. Законы в глоссарий не пишутся руками: каждый `LawSpec` с `kind: 'law'` сам становится термином (`lawTerms`, собирается в `LAB_GLOSSARY`) — название, школьная формулировка и кто открыл (из источников истории закона). Основы выводятся из названия: в украинском меняется первое слово («закон* Фарадея» — «за законом Фарадея»), в английском «Faraday’s law of electrolysis» ищется как «Faraday’s law». Закон, который уже объясняет написанный термин (прихована теплота, тепловий баланс), второй записи не получает.

«Довідник» ([web/library.ts](../web/library.ts)) — отдельная страница рядом с лабораторией, у каждой части свой адрес, как у каталога: `/glossary/` (все термины по алфавиту, `/glossary/#cathode` — сразу к термину), `/substances/` (всё с полки, по семействам), `/equipment/` (приборы и посуд по категориям), по-английски — под `/en/`. Страница строится из тех же данных, что и лаборатория: новый термин, вещество или прибор появляется в ней сам. Карточка вещества или прибора открывает полную справку; поиск — по тексту записей. Каталог, справочник и «Про проєкт» — страницы сайта, на экране всегда одна из них или лаборатория (`go()` в main.ts; ссылки на них — настоящие адреса, открываются на месте, «назад» браузера возвращает). `npm run web:build` пишет и их статические страницы, с текстом в HTML (картинки веществ и иконки приборов дорисовывает лаборатория: они приходят с её сборкой). В офлайн-файле (`npm run web:offline`) они открываются внутри него, адрес не меняется. Старые адреса `#glossary/…` и `#about` переводятся на новые.

### «Про проєкт» и «Знайшов помилку»

**Опір і температура** (9 клас, ЛР № 1 у Кремінського: «Дослідження залежності електричного опору провідника від температури»; [coil-bench.ts](../src/scenarios/coil-bench.ts)): в стакане с водой — катушка тонкого медного провода, её концы — к цифровому мультиметру в режиме «Ω» (диапазон 200 Ом, сотые — оценка), рядом термометр. Катушка при температуре воды; её сопротивление R = R₂₀·(1 + α·(t − 20 °C)), α меди — из компонента (3,93·10⁻³ 1/K, отожжённая медь — обмоточный провод; Wikipedia и HyperPhysics/CRC), R₂₀ ≈ 10 Ом — оценка. Шаги: замер при 20 °C, нагрев кипятильником до 40, 60, 80 °C и замер после каждого. На доске (`Preset.board: 'measurements'`) — только измеренное: R при каждой температуре и α = (R − R₀) / (R₀·Δt); тепловой баланс нагрева здесь лишь путь к температуре и на доску не пишется. Ответ: опір растёт, α ≈ табличному. На сцене — катушка между ногами кипятильника, провода через край стакана к жёлтому мультиметру на столе, на его дисплее — последнее показание. Новая формула `electrical.resistance-temperature` (программа Кремінського, 9 клас); «мультиметр» — в глоссарии. Кнопка шага нагрева теперь называет цель («Нагріти до 40 °C»), лист тетради — нагреватель и термометр в «Обладнанні», шаги стенда — своими словами плана.

**Електромагнітна індукція** (9 клас, ЛР № 5 у Кремінського: «Дослідження явища електромагнітної індукції»; [induct-bench.ts](../src/scenarios/induct-bench.ts), [induction.ts](../src/domains/electrical/induction.ts)): катушка (200 витков, vary 100/200/400; радиус 2 см, длина 4 см, провод 0,3 мм — оценки; сопротивление из удельного сопротивления меди) и миллиамперметр с нулём посередине (±50 мА, деление 2 мА, 1 Ом — оценки). **Атмосферний тиск шприцом** (7 клас, Головко: «вимірювання й визначення: атмосферного … тиску»; [atm-bench.ts](../src/scenarios/atm-bench.ts)): шприц на 1 мл (шкала 0–1 мл длиной 5,7 см — оценка), динамометр, линейка, барометр-анероид (деление 1 гПа). На сцене мяч падает (путь ∝ t²), сплющивается у плиты, подскакивает к следующей вершине и замирает на последней, как на фото; меловые отметки вершин; справа три столбика — Eп, Eк и «тепло» (доли начальной энергии, в сумме всегда вся): высота даёт Eп, остальное механической — Eк, при каждом ударе часть уходит в «тепло». Пластилин падает и расплющивается — всё в «тепло».

**Метод рядів** (7 класс, Головко, «Вступ»: «вимірювання фізичних величин (маси, розмірів малих тіл, …)»; Кремінський, тема 1 «Фізичні величини та їх вимірювання»; Бар'яхтар, розділ 1, експериментальна робота, с. 36; [rows-bench.ts](../src/scenarios/rows-bench.ts)). Новая тема в начале 7 класса — «Фізика як природнича наука. Пізнання природи». Размеры: горошина — среднее геометрическое 7,80 × 6,41 × 5,55 мм ≈ 6,52 мм (Yalçın et al., 2007), зерно проса — 2,07–2,27 мм, берём 2,17 (Singh et al., 2018), нитка № 10 — оценка 0,4 мм; разброс семян одной партии — оценка ±6 % (фиксированная последовательность, не случайная). Шаги: одна горошина (7 мм ± 0,5 — около 7 %), ряд из 15 горошин (98 мм → 6,53 мм), 40 зёрен пшена (87 мм → 2,18 мм), 30 витков нитки на стержне (12 мм → 0,40 мм). Формула `mechanics.row-size` d = L/N, определение `row-method`. Длины этого опыта — в миллиметрах (не в см, как у прочих линеек). На сцене линейка с миллиметровыми делениями (4 единицы на мм, крупнее, чем в жизни), тела падают в ряд по одному, ряд поджимают зубочистки, нитка наматывается виток за витком; скобка с длиной ряда.

**Додавання сил: рівнодійна** (7 класс, Головко: «Додавання сил. Рівнодійна», «вимірювання: … рівнодійної сил»; Кремінський: «Додавання сил, спрямованих уздовж однієї прямої. Визначення рівнодійної кількох сил»; Бар'яхтар § 22, с. 155–156; [forces-bench.ts](../src/scenarios/forces-bench.ts)). Один груз — два тягарця по 100 г на деревянной линейке 30 см (масса линейки — оценка 20 г, она входит в каждое показание одинаково) — держат: одним динамометром за середину (2,2 Н); двумя за концы, тягарці посередине (1,1 + 1,1) и на 6 см от левого конца (1,7 + 0,5 — доли из моментов около концов, F₁ = P·(L − x)/L + P_лін/2; точка 6 см выбрана так, чтобы показания сходились до деления); одним вверх, а вторым вниз с силой 1 Н (3,2 − 1,0). Каждый раз R = 2,2 Н. Формулы `mechanics.resultant` (R = F₁ + F₂) и `mechanics.resultant-opposite` (R = F₁ − F₂), определение `adding-forces`; на доске показания сразу, рівнодійна (`rs:`) — после ответа. На сцене штатив с длинной лапкой справа (формулы доски слева видны), динамометры со стрелкой и выдвигающимся крючком: при разных показаниях линейка наклоняется; нижний динамометр перевёрнут, его кольцо привязано к струбцине на столе. Анимация: пружины покачиваются к показаниям, тягарці переезжают вдоль линейки, нижний динамометр вытягивается рукой медленно, верхний растёт вместе с ним.

**Тело в вязкой жидкости: пузырёк и шарик** (7 класс, Головко: «виявлення пропорційної залежності … прямолінійний рівномірний рух» и «вимірювання … швидкості руху кульки у рідинах різної густини»; [sink-bench.ts](../src/scenarios/sink-bench.ts), [settling.ts](../src/domains/mechanics/settling.ts)). Скорость установившегося движения — из баланса веса, выталкивающей силы и сопротивления: Стокс при Re < 1 (Wikipedia «Stokes' law»), выше — Шиллер–Науман C_d = 24/Re·(1 + 0,15·Re^0,687), Re < 800 (две статьи arXiv); стенки — фактор Факсена (arXiv 2604.26189), только в режиме Стокса. Пузырёк в мыльной жидкости — как твёрдый шарик (ПАВ делают поверхность жёсткой, arXiv 2502.06373). Вязкость — новое поле `viscosity` у жидкой фазы: вода 1,0016 мПа·с (20 °C), глицерин 1,412 Па·с (20 °C), подсолнечное масло 0,04914 Па·с (25 °C) — Wikipedia; средство для посуды — оценка 1 Па·с, 1030 кг/м³. «Бульбашка в пляшці» (по учебнику Бар'яхтара, § 8): пузырьки ≈ 2 и 4 мм, отметки 3–12 см — 14,4 / 28,8 / 43,2 / 57,6 с (s ∝ t) и в 3,7 раза быстрее у большего; `vary` — жидкость (средство или глицерин); новая формула `mechanics.speed` v = l/t (определение `uniform-motion`). «Кулька в рідинах різної густини»: стальной шарик 1,5 мм (vary 1 / 1,5) в мерных цилиндрах — глицерин 0,52 см/с, масло 0,13 м/с, вода 0,54 м/с (Re ≈ 796, на краю корреляции): скорость идёт не за плотностью, а за вязкостью; в воде 15 см за 0,28 с — ответ говорит, что рукой такое не засечь. На сцене бутылка (вверх дном) или цилиндр с отметками, тело у последней отметки, секундомер.

**Гідравлічна машина зі шприців** (7 клас, Головко: «Закон Паскаля. … Гідравлічна машина», «передавання тиску рідинами й газами»; [press-bench.ts](../src/scenarios/press-bench.ts)): два шприца, 5 и 50 мл (внутри 12 и 26 мм — оценки), соединены трубкой с водой. Шаги: линейкой — диаметры поршней; 2, 4, 6 тягарців по 100 г на широком поршне и динамометр давит на узкий, пока груз не поднимется (F₁ = F₂·S₁/S₂ — новый закон `pascal` с историей: Паскаль, 1653, напечатано 1663; формула `mechanics.hydraulic`); узкий поршень на 6 см вниз — широкий поднимается на S₁/S₂ этого. Ответ: выигрыш в силе ≈ отношению площадей (а не диаметров), F₁·l₁ ≈ F₂·l₂ — в работе выигрыша нет; трение поршней не учитывается, и ответ это говорит. На сцене два шприца на столе, трубка под ними, тягарці на широком, динамометр со стрелкой на узком.

**Сполучені посудини** (7 клас, Головко: «Сполучені посудини»; [utube-bench.ts](../src/scenarios/utube-bench.ts)): стеклянная U-образная трубка (внутри 1,6 см — оценка). Сначала вода — уровни в коленах одинаковы; потом в левое колено доливают подсолнечное масло, 10 и 20 мл, линейкой (мм) меряют высоты столба масла и воды справа над уровнем их границы. Равновесие: ρ_олії·h_олії = ρ_води·h_води (новая формула `mechanics.communicating-vessels`) — 5,0 / 4,6 см и 9,9 / 9,2 см; на доске — высоты и плотность масла ρ = ρ_води·h_води / h_олії (до 3 %). Вопрос «где уровень выше» — масла. На сцене трубка на штативе, вода синяя, масло жёлтое, граница опускается слева на столько, на сколько вода поднимается справа (объём воды тот же).

**Тиск рідини й глибина** (7 клас, Головко, тема 3: «Дослідження … зміни тиску в рідині з глибиною; вимірювання … гідростатичного тиску»; [depth-bench.ts](../src/scenarios/depth-bench.ts)): в литровом стакане 12 см жидкости (вода, солёная вода 20 % или подсолнечное масло — `vary`), воронку с резиновой плёнкой опускают на 3, 6, 9 см, на 9 см поворачивают плёнкой вбок; трубка ведёт к U-образному манометру с водой. Давление p = ρ·g·h (новая формула `mechanics.hydrostatic-pressure`), манометр показывает Δh = p / (ρ_води·g) с миллиметровыми делениями. На доске p = ρ_води·g·Δh и плотность жидкости ρ = p / (g·h); ответ — «пропорционально глубине» (разброс p/h сравнивается с полуделением манометра), плотность найдена до 3 %, вбок — те же Δh (закон Паскаля). На сцене стакан с линейкой, воронка на глубине, манометр с разницей уровней.

В карточке — «▶ Почати» (настоящая ссылка на страницу опыта: роботам и «открыть в новой вкладке»; в лаборатории открывается на месте, «назад» возвращает в каталог), «ⓘ Детальніше» (лист тетради в окне, со своим «Почати») и 🔗 (поделиться). ## Объяснения: «что участвовало в расчёте»

1. Солвер получает `ctx.trace` и пишет `TraceRecord`: id формулы из каталога, объекты, **точные аргументы** и результат. Без `trace` — нулевая стоимость.
2. `runExperiment` собирает статистику использования формул за весь прогон; `traceTick` пересчитывает один шаг из снимка с полной трассой («объясни момент t») — возможно, потому что физика чистая и детерминированная.
3. Тест `trace-consistency` повторно вызывает функцию каталога на аргументах из трассы и сверяет результат: объяснение не может разойтись с расчётом.
4. Формула → закон (`LawSpec`): формулировка по уровням, авторы (даты из Wikidata), история с цитатами, границы применимости. `role: 'associated'` — когда единственного «открывателя» нет.
5. `buildReport` строит `Block[]` по уровню (novice / school / advanced / expert), языку (`uk`, `en`) и стране программы (`UA`); консоль рендерит текстом, веб отрендерит карточками и KaTeX.
6. Ни ядро, ни тексты не предполагают конкретную страну: язык — ключ в `LocalizedText`, классы — только в `CurriculumRef` с кодом страны. Правила тона — [CONTENT_STYLE.md](CONTENT_STYLE.md).

Разбор «цель против результата» ([LEARNING_MODEL.md](LEARNING_MODEL.md)): солвер пишет `TransferRecord` — точную энергию по каждой связи за шаг; `runExperiment` суммирует их в `result.transfers`. `analyzeTemperature` раскладывает итоговую температуру тела на «простой расчёт» + вклад каждого участника (сумма сходится до 1e-9). `Expectation` (прогноз/цель) — необязательна; `solveKnob` бисекцией переигрывает опыт и находит, какой параметр как изменить.

Команды делятся на `control` (управление), `matter` (долить — приносит свою энергию) и `intervention` («режим бога» — энергия извне записывается), поэтому баланс энергии всегда сходится.

## Многодоменность (как будут жить вместе)

```ts
createSimulation({
  solvers: [electricalSolver, jouleCoupling, thermalSolver, mechanicsSolver],
  fixedDt: seconds(0.01),
});
```

Операторное расщепление: каждый солвер по очереди делает свой шаг. Связка доменов — через общие сущности: электрический решатель задаёт мощность «ведомого» теплового источника (`driven` burner), тепловой её разносит; домены не импортируют друг друга.

## Известные ограничения MVP (осознанно)

- Lumped-модель: одна температура на объект (без распределённых полей). Поэтому у сухой соли в кастрюле одна температура на всю насыпь, хотя нижний слой на деле горячее верхнего.
- Растворы — растворение и кристаллизация мгновенны, размер кристаллов не считается. Пересыщенный раствор держит только вещество с `inWater.supersaturates` (натрий ацетат): без затравки оно не кристаллизуется никогда (метастабильной границы и самопроизвольного зарождения в модели нет), остальные кристаллизуются, как только раствор насыщен. Смешивание идеальное, кроме спирта с водой (ван Лаар); CuSO₄ считается как кристаллогидрат; теплота растворения (`inWater.enthalpyOfSolution`, CRC) берётся для бесконечно разбавленного раствора при любой концентрации; у сахара, медного купороса и соды её пока нет (нет проверенного источника), и растворение у них температуру не меняет.
- Явная схема: для очень жёстких сцен — ограничение подшагов и понятная ошибка; позже — неявный Эйлер.
- `kind` — строки, сущности домена проверяются type guard-ами. При росте числа доменов — реестр `EntityKindRegistry` с описанием параметров (для автогенерации панели свойств в UI).

**Шаг 2 — электрическая цепь постоянного тока** (`src/domains/electrical/`):
